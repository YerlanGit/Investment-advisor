# freedom-etl — сбор дневных котировок (T-1) Tradernet → TimescaleDB
<!-- nav | area:etl | code:freedom-etl/ | read-before:правка сбора котировок, батчинга, схемы daily_candles -->

Сервис ежедневно догружает дневные свечи (OHLCV) по бумагам США (NYSE, NASDAQ)
и Казахстана (KASE) из API Tradernet в собственную TimescaleDB. Хранилище
питает расчёт риск-метрик (VaR, волатильность, коэффициент Шарпа).

Сервис самодостаточен: свой образ, свои зависимости, своя БД. От основного
приложения RAMP (`src/`) он не зависит и не импортируется в него.

---

## 1. Быстрый старт

```bash
cd freedom-etl
cp .env.example .env            # заполните TRADERNET_PUBLIC_KEY / _SECRET_KEY

docker compose up -d timescaledb        # поднять БД
docker compose run --rm etl --init-db   # применить схему
docker compose run --rm etl --once      # первичная загрузка (идёт долго)
docker compose up -d                    # демон с ежедневным кроном
```

Локально, без Docker:

```bash
pip install -r requirements.txt
python main.py --once
```

### Режимы CLI

| Команда | Что делает |
|---|---|
| `python main.py` | демон: применяет схему и ждёт крона |
| `python main.py --once` | один прогон синхронизации, выход с кодом 0/1 |
| `python main.py --init-db` | только миграции схемы |
| `python main.py --seed AAPL.US,MSFT.US` | добавить тикеры в универсум |

`--once` — то, чем делается первичная загрузка (5 лет × универсум идёт
десятки минут) и чем догоняется пропущенный прогон после простоя.

## 2. Как устроен конвейер

```
tracked_tickers ─┐
                 ├─► план окон ─► батчи ≤50 ─► getHloc ─► Transform ─► UPSERT ─► sync_status
sync_status  ────┘   (по дате)     (пауза 2с)              (пояс биржи)  daily_candles
```

| Файл | Ответственность |
|---|---|
| `config/config.py` | все настройки из env, клампы лимитов |
| `db/models.py` | DDL, доменные типы, SQL-операторы UPSERT |
| `db/connection.py` | пул asyncpg; **весь** SQL заперт здесь |
| `services/auth.py` | HMAC-SHA256, заголовки `X-NtApi-*` |
| `services/tradernet_client.py` | HTTP, батчинг, троттлинг, backoff, разбор `getHloc` |
| `services/etl_processor.py` | бизнес-логика T-1: окна, отсев, порядок записи |
| `main.py` | планировщик APScheduler и CLI |

## 3. Схема данных

```sql
daily_candles                          -- гипертаблица, чанк 365 дней
    ticker      VARCHAR(20)    NOT NULL
    trade_date  DATE           NOT NULL
    open/high/low  NUMERIC(12,4)
    close       NUMERIC(12,4)  NOT NULL
    volume      BIGINT
    PRIMARY KEY (ticker, trade_date)   -- контракт идемпотентности

sync_status      (ticker, last_synced_date, updated_at)   -- курсор ETL
tracked_tickers  (ticker, exchange, is_active, added_at)  -- универсум
```

`tracked_tickers` добавлена сверх ТЗ: стадия Extract начинается со списка
отслеживаемых бумаг, а читать его было неоткуда. Хранить универсум в env
нельзя — он меняется чаще, чем передеплоивается сервис.

Чанк в год, а не дефолтные 7 дней: у дневных свечей на недельный чанк
приходится ≈5 строк на тикер, и пятилетняя история распалась бы на сотни
чанков, обход которых дороже чтения самих данных.

## 4. Протокол Tradernet

Транспорт — APIv3, сверено с исходником официального SDK `tradernet-sdk` 2.2.0
(`tradernet/core.py::authorized_request`, `common/string_utils.py`):

```
POST {base}/api/getHloc          Content-Type: application/json

payload   = json.dumps(params, separators=(",", ":"))
timestamp = str(int(time.time()))
X-NtApi-Sig = HMAC_SHA256(secret_key, payload + timestamp).hexdigest()
X-NtApi-PublicKey, X-NtApi-Timestamp
```

Параметры `getHloc`:

| Параметр | Значение | Замечание |
|---|---|---|
| `id` | `"AAPL.US,MSFT.US,…"` | батч до 50 тикеров через запятую |
| `timeframe` | `1440` | **минуты**, не секунды и не `"D"` |
| `date_from` / `date_to` | `"01.08.2026 00:00"` | формат `DD.MM.YYYY HH:MM` |
| `intervalMode` | `"ClosedRay"` | закрытый интервал |
| `count` | `-1` | все свечи в интервале |

### Три ловушки, каждая из которых стоит часов отладки

1. **ISO-даты не ошибка, а пустота.** `date_from=2026-08-01` сервер примет и
   вернёт `200 OK` с пустым массивом свечей. Обязателен `DD.MM.YYYY HH:MM`.

2. **Порядок колонок — `[high, low, open, close]`**, буквально «hloc», а не
   OHLC. Прочитать как OHLC — тихая катастрофа: `close` станет `low`, ряд
   доходностей окажется смещённым и при этом правдоподобным. Подтверждено
   README SDK: `columns=["high","low","open","close"]`.

3. **Ошибки приезжают с HTTP 200** в теле (`code`, `errMsg`). `code=4` —
   подпись, `code=12` — учётные данные; оба повтором не лечатся.

Форм ответа три (разные региональные шлюзы), поддержаны все —
см. `parse_hloc_response`. Ответ изначально имеет форму словаря по тикеру,
поэтому батчинг через запятую и работает.

## 5. Лимиты и устойчивость

| Ограничение | Значение | Где зашито |
|---|---|---|
| Тикеров в батче | ≤ 50 | `TradernetClient.MAX_BATCH_SIZE` |
| Пауза между запросами | ≥ 2.0 с | `TradernetClient.MIN_REQUEST_INTERVAL` |
| Повторы при 429 | 5, экспоненциально + джиттер | `_sleep_backoff` |
| `Retry-After` | сильнее собственного расчёта | `_parse_retry_after` |

Оба лимита зажимаются **в конструкторе клиента**, а не только в конфиге:
конфиг можно обойти прямым вызовом из скрипта, конструктор — нет. Уменьшить
паузу через env невозможно, и это осознанно: учётная запись у сервиса одна,
«ускорить выгрузку» — самый вероятный способ потерять её целиком.

Троттлинг живёт **внутри** клиента, поэтому пауза не может потеряться при
рефакторинге цикла снаружи, и она же разносит повторы.

Дополнительно повторяются: 5xx и 403 с HTML-заглушкой Cloudflare (регулярный
сценарий для облачных IP). Обычные 4xx падают сразу — повтор их не лечит.

## 6. Инварианты (не сломать)

- **Идемпотентность** — `PRIMARY KEY (ticker, trade_date)` + `ON CONFLICT DO
  UPDATE`. Повторный прогон за тот же день физически не создаёт вторую строку.
- **Сначала свечи, потом курсор.** Обратный порядок теряет данные молча: упади
  процесс между обновлением `sync_status` и записью — день числится
  загруженным, не будучи записанным, а курсор только растёт и назад не вернётся.
- **`GREATEST` в курсоре.** Один частичный ответ брокера не должен откатить
  `last_synced_date` — это бесконечная перезагрузка уже лежащей истории.
- **Часовой пояс биржи.** Торговая дата считается в поясе биржи, а не в UTC:
  в 01:00 UTC 6-го числа в Нью-Йорке ещё 5-е, и `.date()` по UTC записал бы
  сессию не тем днём.
- **`volume is None` ≠ `volume == 0`.** Первое — «не сообщили» (бумага
  остаётся), второе — «торгов не было» (свеча отсеивается как ложный нулевой
  доход, занижающий σ).
- **Незакрытый день не пишется.** Внутри сессии `close` — последняя сделка, а
  не цена закрытия.
- **`COALESCE` в UPSERT свечей.** Повторный проход, отдавший только закрытие,
  не должен обнулять уже сохранённые O/H/L.
- **Весь SQL — в `db/connection.py`.** Иначе инвариант идемпотентности
  размажется по слоям, и первый «быстрый фикс» вернёт дубликаты.

## 7. Расписание

Крон: **03:00 America/New_York** — пост-маркет США закрыт, клиринг брокера
прошёл; это ≈12:00 по Астане.

Задано **именем зоны**, а не UTC-часом: США переходят на летнее время, и
`0 8 * * *` в UTC дважды в год уезжал бы на час — в марте прогон начинался бы
до окончания клиринга и записывал неполный день.

`misfire_grace_time=3600` — пропущенный прогон (контейнер лежал) состоится при
старте, а не через сутки. `max_instances=1` — две копии не пишут одни строки и
не жгут лимит на одном ключе.

## 8. Тесты

```bash
cd freedom-etl
python -m pytest tests/ -q          # → 109 passed
```

Сеть и БД не трогаются: клиент принимает готовую сессию, БД подменена
журналирующим двойником, `asyncio.sleep` — счётчиком (поэтому тест
утверждает, что backoff растёт экспоненциально, а не что «что-то поспало»).

Тесты проверены на способность падать — пять мутаций, каждая поймана
ровно тем тестом, который её стережёт:

| Мутация | Поймана |
|---|---|
| `hloc` прочитан как `ohlc` | `test_shape_a_parallel_arrays_column_order_is_hloc` |
| курсор двигается до записи свечей | `test_candles_are_written_before_the_cursor_moves` |
| `volume=None` трактуется как `0` | `test_missing_volume_is_kept` |
| убран `GREATEST` из курсора | `test_sync_cursor_can_only_move_forward` |
| торговая дата взята в UTC | `test_trade_date_uses_exchange_not_utc` |

Прогон **не входит** в основную сюиту репозитория (`PYTHONPATH=src python -m
pytest tests/ -q`): это отдельная единица поставки со своими зависимостями,
и её `conftest.py` действует только внутри `freedom-etl/tests/`.

## 9. Известные ограничения

- **Корпоративные события не обрабатываются.** Сплиты и дивиденды в
  `daily_candles` не корректируются — таблица хранит то, что отдал брокер.
  Основное приложение RAMP решает это тремя слоями в
  `src/freedom_portfolio/history.py` (`corr=1`, таблица `KNOWN_SPLITS`,
  эвристика по скачку > 33%). Потребителю этой БД корректировку нужно
  применять самому либо перенести те слои сюда.
- **Домен API зависит от юрисдикции счёта.** Ключи счёта, открытого в РК,
  могут не аутентифицироваться на `tradernet.com` — тогда нужен
  `TRADERNET_API_URL=https://tradernet.kz` или `https://freedombroker.kz`.
- **Универсум наполняется вручную** (`SEED_TICKERS` / `--seed`);
  автосинхронизации со списком бумаг брокера нет.
- **Неизвестный суффикс биржи** даёт UTC и предупреждение в лог. Для рынков
  за пределами US/KZ добавьте зону в `_EXCHANGE_TZ`.
