### 1.1 Выходные дни грузить НЕ НУЖНО (кроме крипто)

Вопрос владельца. Ответ следует из замеров, уже сделанных проектом:

* **Субботний срез Stooq содержит РОВНО НОЛЬ US-баров** — замерено на
  2026-08-08: 258 строк, все крипто (`§−76`; константа `MIN_US_ROWS` и
  комментарий к правилу 9 в `stooq_ingest.py`). Грузить нечего.
* **Календарь рынка ВЫВОДИТСЯ из данных**: сессия — это дата, по которой у
  рынка есть хоть один бар (`stooq_store.sessions`). Суббота не становится
  сессией US, потому что US-баров в ней нет.
* **Свежесть бумаги считается в ТОРГОВЫХ днях её рынка**
  (`staleness_trading_days`). Пропущенная суббота не старит ни одну US-бумагу
  ни на день.
* **Правило 9 имеет форму `0 < принято < порога`** именно ради этого: ноль
  US-баров = закрытый рынок, а не недокачанный файл. Праздники обрабатываются
  сами собой, список праздников не нужен.

🔴 **Единственное исключение — крипто.** Суффикс `.V` → рынок `CRYPTO`, у
которого 7 сессий в неделю (`_EXPECTED_SESSIONS_PER_WEEK`). Если в книге есть
крипто-бумага, пропуск выходных создаёт в её ряду НАСТОЯЩИЕ дыры: по
`MAX_STALE_TRADING_DAYS = 5` она уйдёт в `failed` и выпадет из матрицы. У
книги 148046720 крипто нет (строка мандата «Крипто» = 0.0 %), поэтому сегодня
выходные не нужны вовсе.

⚠️ **Что действительно ограничивает — пропуск БУДНИХ дней.**
`MAX_MARKET_STALE_DAYS = 7` считается в КАЛЕНДАРНЫХ днях от сегодня
(`market_staleness_days`) — отдельный гард, потому что при полностью
остановленной заливке потикерная свежесть честно рапортует 0 у всех бумаг
сразу (`§−80`). Выходные съедают 2 дня из этих 7 бесплатно: после пятничной
заливки база блокирует ручной отчёт со следующей **субботы**.

## 2. Карта происхождения данных: что снаружи, что считается

> Прямой ответ на вопрос владельца. Замерено по коду, а не по документации.

### 2.1 Внешние источники — ровно шесть адаптеров

**Ни один расчётный модуль `finance/` не делает сетевых вызовов** (проверено
сканом: 0 вхождений `requests`/`httpx`/`urlopen` во всех вычислительных
файлах). Внешний мир входит в проект только здесь:

| Источник | Модуль | Что приносит | Куда попадает в отчёте |
|---|---|---|---|
| **Tradernet (Freedom Broker)** | `freedom_portfolio/client.py` | состав портфеля, количество, цена покупки, текущая цена, дневные свечи (OHLC) | «Что вы держите», NAV, P&L, вся история для риск-метрик |
| **Stooq** (ручной путь) | `finance/stooq_store.py` | дневные свечи из локальной SQLite, залитой оператором | то же самое, но для `source='manual'` |
| **SEC EDGAR** | `finance/sec_edgar.py` | ROE, маржа, долг/активы, рост выручки, FCF, Altman-Z, Piotroski-F, покрытие процентов | карточка «Фундаментал», пиллары **F** и **C** |
| **FRED (St. Louis Fed)** | `services/macro_data.py` | 6 рядов: кривая 10Y−2Y, HY-спред, VIX, инфляционные ожидания, безработица, ВВП | панель «Сигналы-драйверы», оверлей режима |
| **FRED** (курсы) | `services/fx_feed.py` | дневной курс USD/KZT (`DEXKZUS`) | Base Currency Approach: пересчёт позиций в USD |
| **FRED** (кредит) | `finance/cds_feed.py` | прокси кредитного спреда | пиллар **C** (Credit) |
| **ChromaDB (локально)** | `agent/rag_engine.py` | выдержки из отчётов GS / MS / JPM | цитаты в подтверждении режима |
| **Anthropic API** | `ai_narrative.py` | ТОЛЬКО ТЕКСТ — ни одного числа | вердикт, комментарии секций |

🔴 **ИИ не считает ничего.** Модель получает уже посчитанные числа и обязана
их цитировать; выдумывать суммы и адресаты ей запрещено промптом и проверяется
пост-фильтрами (`§−44` R-5, `§−90` A-5).

## 4. Связность слоёв: измерено, а не описано

AST-обход всех импортов `src/`:

```
L1 Data     → L0 Cross     6   ↓
L2 Engine   → L1 Data     17   ↓
L2 Engine   → L0 Cross    13   ↓
L3 Report   → L2 Engine   10   ↓
L3 Report   → L0 Cross     1   ↓
L4 Delivery → L2 Engine    7   ↓   ← бот зовёт движок
L4 Delivery → L3 Report    5   ↓   ← бот зовёт сборку отчёта
L4 Delivery → L1 Data      4   ↓
L4 Delivery → L0 Cross     4   ↓
```

**57 межслойных рёбер, все вниз. Нарушений нет.** Единственный импорт «вверх»
(`demo_portfolio` → `investment_logic`) — ЛЕНИВЫЙ, внутри функции: легитимный
приём против цикла, гейт `test_layering` зелёный.

**Как связаны бот, логика и математика.** Связь односторонняя и узкая:

```
tg_bot.cb_confirm
  └─ _resolve_portfolio_source()      → freedom | manual | demo | undetermined
     └─ analyze_all(source=df)        → 36 ключей results{}      [L2 математика]
        └─ build_payload(results)     → 94 ключа payload         [L3 формат]
           └─ build_design_data()     → 14 (BASE) / 37 (DEEP)    [L3 вид]
              └─ render_premium()     → HTML → GCS → ссылка      [L4 доставка]
```

Бот **не считает ничего** и не форматирует: он выбирает источник, зовёт движок,
отдаёт результат рендеру и списывает токен ПОСЛЕ доставки. Слой отчёта не
импортирует `tg_bot` (инверсия запрещена гейтом). Это и есть причина, по
которой ручной ввод удалось сделать паритетным: он меняет ровно одну развилку
в начале цепочки, а не ветвится по всему конвейеру.
