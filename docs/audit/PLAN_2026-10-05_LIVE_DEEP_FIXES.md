## 0. Каким путём построен разобранный отчёт — проверить ПЕРВЫМ

Владелец сообщил, что выбирал «🌐 Freedom + ручной». Сам отчёт говорит другое:

| Что записано в HTML DEEP #2 | Что записал бы режим «Freedom + ручной» (`aggregated`) |
|---|---|
| CoVe «Состав портфеля»: **Ручной ввод пользователя** · «количество и цена покупки введены пользователем…» | **Freedom Broker (N поз.) + ручной ввод** (`data_lineage._aggregated_source_status`) |
| CoVe «Цены и история»: **Stooq (публичные котировки)** | **Tradernet (Freedom Broker)** — D-1/I-13: Tradernet для ВСЕХ колонок |
| Позиции: только 6 ручных бумаг + USD | Позиции счёта Freedom + ручные |
| Пометки «Freedom Broker был недоступен» нет | — |

Подпись не может ошибиться в эту сторону: `aggregated` ставит `_ramp_source=aggregated`
(`aggregator.py:181`) и цены `TradernetProvider` (`price_providers.py:279`). Значит, расчёт
шёл по ветке `manual`. Из «Freedom + ручной» в неё ведут ровно два пути без пометки в CoVe:

1. **Пустой счёт Freedom.** `FreedomSource.load` → `failure_reason="empty"`, и
   `_aggregated_step1` отказывает ещё до гейта (гейт I-15 отказал бы так же — «счёт пуст»,
   `gate.py:51`); бот пишет «📭 На счёте Freedom нет позиций —
   агрегированный отчёт совпал бы с ручным» и даёт кнопку **«📈 Сгенерировать отчёт по
   ручным активам»** (`rptgo:manual:<тир>`, `tg_bot.py:3690`). Это ручной отчёт на Stooq.
2. **Кнопка на экране ручного портфеля** «📊 Отчёт по ручному портфелю» (`src:manual`,
   `tg_bot.py:3184`) или пункт «✏️ Ручной портфель» в «📊 Новый отчёт» — это уже не
   «Freedom + ручной», но выглядят соседями.

(Сбой брокера ведёт на `fb:manual:<тир>:<причина>` — тогда CoVe пишет «Freedom Broker был
недоступен (…)»; в отчёте этого нет.)

**Проверка по логам** (у агента нет доступа к логам прода):

```bash
gcloud logging read 'resource.type="cloud_run_revision" AND textPayload:"user=148046720"
  AND (textPayload:"HYBRID:" OR textPayload:"PORTFOLIO SOURCE")' \
  --freshness=7d --limit=50 --format='value(timestamp,textPayload)'
```

`HYBRID: user=… freedom_ok=False reason=empty` — путь 1; `PORTFOLIO SOURCE: manual` без
строки `HYBRID` — путь 2.

**Главный вывод раздела.** Ни одна из восьми находок не зависит от режима: в
`aggregated` цены и история УЖЕ берутся из Freedom (Tradernet `getHloc`), но **секторов из
Freedom не берёт ни один режим** — ни один вызов API их не запрашивает, позиция Tradernet
(`freedom_portfolio/models.Position`) поля сектора не несёт. Переключение на Freedom
поменяет котировки, но не исправит ни один пункт ниже. Поэтому план чинит движок, а не
источник.

### Задачи, родившиеся из раздела 0

- **U-1 · Режим не виден пользователю** (🟠, без смены чисел). Отказ «Freedom + ручной»
  превращается в ручной отчёт одной кнопкой, а на обложке и в сообщении доставки источник
  не назван — владелец принял Stooq-отчёт за Freedom. Исправление: бейдж на обложке
  («Ручной портфель · цены Stooq» / «Freedom + ручной · цены Tradernet»), та же строка в
  сообщении «📊 … готов»; текст кнопки на отказе — «📈 Отчёт по ручным активам (цены
  Stooq, без данных Freedom)». Тест: бейдж = `portfolio_source` + `_price_source_label`.
- **D-0 · решение владельца:** считать ли **пустой, но авторизованный** счёт Freedom
  доказательством I-15. Брокер ПРИНЯЛ личные ключи в этом же запросе — статус клиента
  доказан; сейчас гейт отказывает только из-за отсутствия позиций. «Да» → «Freedom +
  ручной» при пустом счёте строится на Tradernet (правка `gate.py:51` и ветки `empty` в
  `_aggregated_step1`, строка CoVe «Freedom Broker (0 поз.) + ручной ввод»). Это
  юридическая граница I-12, решать не агенту.

## 2. Разбор по пунктам

### 2.1 🔴 Секторы: «Other 89%», «Доля IT 0%», индекс риска +10

**Симптом.** FTNT, TXN, PEP, PGR, XLU — сектор `Other` (83.7% NAV, 88.8% длинной книги).
Предупреждение «Other: 89% — превышен мягкий лимит 40%», «Доля IT 0.0% → 0.0%» (FTNT+TXN =
26.6% NAV), индекс риска 47 вместо 37 (пересчитано `composite_risk_score`: аггравотор
`sector_top_pct=88.8` даёт ровно +10), V-пиллар сравнивает P/E с `default` (20×), а не с
технологиями (28×) или полупроводниками (25×), — и проза «дорого даже для своего сектора»
ложна.

**Механизм.** Сектор знает только словарь `risk_engine.TICKER_SECTOR` (`:491`, ≈50
тикеров, собран под живую книгу владельца), неизвестное → `Other` (`get_ticker_sector`,
`:1153`). Это СЕДЬМАЯ копия фактов о тикере вне SSOT `asset_taxonomy` —
`NoSecondCopyTest` её не видит (`risk_engine` нет в `_CONSUMERS`). Потребители сектора:

| Потребитель | Где | Что ломается при `Other` |
|---|---|---|
| Секторная панель и предупреждения | `pdf_payload.py:1790, :1897` | ложное «89% > 40%» |
| Аггравотор индекса | `portfolio_manager.py:1172` → `asset_taxonomy.top_sector_concentration_pct` → `scoring.composite_risk_score` | +0…10 пунктов |
| F/V-ориентиры SEC | `portfolio_manager.py:767` → `scoring_orchestrator._SECTOR_*_BENCHMARKS` | сравнение с `default` |
| Наклон режима в F | `regime.REGIME_FAVOURED/PENALISED_SECTORS` | наклон теряется |
| Техникалс | `portfolio_manager.py:1280` | — |
| Реинвест и «Доля IT» | `portfolio_manager.py:1552` → `simulate._it_share` | IT 0%, деконцентрация слепа |
| Промпт ИИ | `ai_narrative` `sectors` | «88.8% в прочих» |

**Где ещё.** Во всех режимах: Freedom-клиент с бумагой вне словаря получает то же. Ручной
ввод лишь чаще выводит за словарь (вселенная Stooq ≈ 800 бумаг).

**Исправление — два шага.**

*1a (Ф1-a, без сети, без новой методологии):* **«сектор не определён» — это пробел данных,
а не сектор.** `Other` не участвует в `top_sector_concentration_pct` и в мягком лимите 40%;
вместо предупреждения — строка качества «сектор не определён: 83.7% NAV (5 бумаг)» и
условная строка CoVe `degrade`; «Доля IT» при неизвестном секторе > 20% книги — «н/д», а не
«0.0%» (правила `§−90`: неизвестное → «внимание», пустое ≠ «всё хорошо»). Модели —
`sector_unknown_pct`, чтобы она не писала «88.8% в прочих».
На этой книге: индекс 47 → 37, ложное предупреждение уходит.

*1b (Ф2):* **источник сектора — цепочка, факты — в SSOT `asset_taxonomy`.**

0. **Замер (Ф0).** Документация Tradernet (`github.com/tradernet/tn.api`, SDK
   `tradernet-sdk` 2.2.0) поля сектора не описывает; кандидаты — `getStockData`
   (карточка бумаги) и `getSecurityInfo` с `sup=false`. Проверить одним вызовом с ключами:

   ```bash
   FREEDOM_API_KEY=… FREEDOM_API_SECRET=… PYTHONPATH=src python - <<'EOF'
   import json, os
   from freedom_portfolio.client import TradernetClient
   c = TradernetClient(os.environ["FREEDOM_API_KEY"], os.environ["FREEDOM_API_SECRET"])
   for cmd, p in (("getStockData", {"ticker": "FTNT.US", "lang": "ru"}),
                  ("getSecurityInfo", {"ticker": "FTNT.US", "sup": False})):
       r = c._with_cf_retry(c._post_v2_signed, cmd, p)
       print(cmd, json.dumps(r, ensure_ascii=False)[:4000])
   EOF
   ```
   Ищем `sector` / `industry` / `отрасль`. Есть — звено 2 ниже включается; нет — цепочка
   работает без него.
1. **ETF — статическая таблица** `SECTOR_BY_ETF` в `asset_taxonomy` (XLU → Utilities,
   XLK → Technology, XLP → Consumer Staples, SOXX → Semiconductors, …); широкие ETF
   (SPY/QQQ/VTI) — «широкий рынок», в концентрацию не входят.
2. **Freedom** — ТОЛЬКО для `freedom`/`aggregated` и ТОЛЬКО за тем же гейтом, что цены
   (I-12/I-15): ручному отчёту Tradernet недоступен и для сектора.
3. **SEC EDGAR** `data.sec.gov/submissions/CIK##########.json` → `sic` → таблица
   SIC → сектор. Публичный источник, законен для `manual`; модуль `sec_edgar` уже ходит в
   EDGAR (10 запросов/с), кэш 30 дней рядом с кэшем CDS.
4. Иначе — «не определён» (шаг 1a).

Цепочка — новая стадия движка `_stage_sectors` сразу после цен (правило оркестратора:
новая логика = новая стадия; пин порядка в `test_engine_orchestrator.py` обновляется
осознанно); `get_ticker_sector` сначала читает разрешённую карту. `TICKER_SECTOR`
переезжает в `asset_taxonomy`, `risk_engine` — в `_CONSUMERS` гейта SSOT (отдельный PR
рефакторинга ДО правки поведения).

**D-6 · решение владельца: словарь секторов.** Нынешний словарь сливает защитные и
циклические «Consumer» и не знает Utilities/Communication/Real Estate. Предложение —
11 секторов GICS + `Semiconductors` (отдельный фактор SOXX) + `Bonds`/`Gold`/`Commodities`/
`EM_Kazakhstan`. Тянет за собой: таблицы режима (в Slowdown: Utilities и Consumer Staples —
в «выигрывающие», Consumer Discretionary — в «проигрывающие»), ориентиры F/V для новых
ключей (до калибровки — `default`), русские подписи и цвета панели.

**Не ломаем.** SSOT фактов (`asset_taxonomy`), I-12 на секторах, «числа — в `finance/`».

**Тесты.** Неизвестный сектор не двигает индекс и не даёт предупреждения; IT = «н/д» при
неизвестном; цепочка ETF → Freedom → SEC → unknown с подменёнными провайдерами; `manual`
не вызывает Tradernet за сектором (I-12); SSOT-гейт видит `risk_engine`.
**Эталоны.** Тикеры фикстур (AAPL/MSFT/TLT/KSPI/CONL…) уже в словаре — изменения
ожидаются только в флагах; проверить, обновить осознанно.

**Ожидаемо на этой книге (после 1b):** Tech-комплекс 28.3% длинной книги (FTNT+TXN),
Finance 25.5% (PGR), Utilities 19.4% (XLU), Consumer Staples 15.6% (PEP), Bonds 11.2%;

### 2.2 🔴 Кредитный пиллар: −2 у каждой американской бумаги

**Симптом.** C-пиллар: FTNT −2.0, XLU −2.0, PEP −1.5, PGR −1.5, TXN −1.0. Отсюда четыре
Sell из шести. PEP/TXN/PGR — эмитенты с рейтингом A, у XLU эмитента нет вовсе.

**Механизм.** `CDSFeed` (`cds_feed.py:345`) при отсутствии CDS эмитента подставляет
ИНДЕКС спреда мусорных облигаций США (FRED `BAMLH0A0HYM2`, 312 б.п.) для ЛЮБОГО
американского тикера (`_fred_hy_provider`, `:400`). `credit_score` читает его как CDS
эмитента: `≥150 б.п. → −2` (`scoring.py:247`). Индекс HY за всю историю ряда не опускался
ниже 150 б.п. — значит, это не сигнал, а постоянный сдвиг −2 у всех. Метка качества «C» у
прокси записывается, но в оценке не используется. Правило «Δ7д > +20% → −2» тоже рыночное
и бьёт по всем сразу. У XLU (ETF без собственной отчётности) guard применимости
(`scoring_orchestrator._is_credit_not_applicable`, `:77`) не срабатывает: он знает
суверенные/сырьевые ETF и LETF, но не акционные ETF.

**Оценка эффекта (по разложению пилларов из отчёта, «C только из SEC-слоя»):** TXN −1.3 →
≈ +0.7, PGR −2.7 → ≈ −0.7 (hotspot → Trim), PEP −3.8 → ≈ −1.8 (Trim), FTNT −2.1 → ≈ −1.1
(Trim; точное значение скрыто клипом −2), XLU −3.0 → −1.0 (Trim, C и F — «н/д»). Вместо
«продать четыре бумаги» — «урезать», что согласуется с тем, что в книге нет ни одной
бумаги в кредитном стрессе.

**D-3 · решение владельца.**
- **A (рекомендую):** рыночный прокси — не кредит эмитента. Точки качества «C» в ветку CDS
  `credit_score` не попадают; C = только SEC-слой (Altman / Piotroski / покрытие процентов).
  Рыночный кредитный режим и так виден там, где ему место, — в драйверах режима (HY OAS там
  уже есть). Ветка CDS остаётся для данных эмитента качества A/B (платный провайдер).
- B: относительный прокси (z-оценка HY к своей истории, ±0.5 всем) — по-прежнему не
  различает бумаги и дублирует режим.
- C: IG-прокси (`BAMLC0A0CM`) для инвестиционного уровня — нет данных о рейтингах, честно
  не реализуется.

**В обоих случаях:** акционные ETF (`asset_taxonomy.EQUITY_ETFS`) — F и C «н/д», как LETF
(P-6): у обёртки нет эмитента. Строка CoVe «CDS spreads» переписывается: «рыночный
HY-спред — контекст режима, в оценку эмитента не входит».

**Тесты.** HY 312 б.п. не меняет C эмитента; данные качества A/B меняют; XLU/SPY — F/C «н/д»;
фикстуры работают без CDS (`cds_lookup=None`) — эталоны должны остаться прежними, кроме
флагов применимости у акционных ETF (в фикстурах их нет — проверить).

### 2.3 🟠 Стресс занижает потери защитной книги

**Симптом.** «Tech sell-off (как Q2 2022)»: портфель −2.3%, хотя одна рыночная бета 0.57 ×
(−10%) даёт −5.7%.

**Механизм.** Каталог (`stress.py:143+`) задаёт 2–4 фактора на сценарий; остальные по
семантике F-1 считаются «сырое движение 0». После ортогонализации (стилевые/EM-факторы
очищены от рынка) `residualize_shocks` (`:223`, ветка `:248`) даёт неназванному фактору
остаток −β̂·шок_родителя: при SPY −10% низковолатильный SPLV, VLUE, IWM, EEM «стоят» —
то есть РАСТУТ относительно рынка на ≈β·10%. Книга с β Volatility 0.59 получает крупную
положительную ногу. Семантика закреплена тестом
`test_phase25.test_unnamed_child_gets_counter_leg`, — это решение, а не опечатка; дефект в
том, что «акции low-vol, value, small-cap и EM не упали при −10% рынка» неправдоподобно.
Вторая неточность: «как Q2 2022» при SPY −10%, тогда как S&P 500 за Q2 2022 упал на ≈16%
(комментарий в коде это признаёт).

**D-4 · решение владельца.**
- **A (рекомендую, дёшево):** «неназванный фактор движется со своим родителем»
  (условное среднее): сырое движение = Σβ̂·шок_родителя, остаток 0. Инвариантность
  raw↔orth сохраняется (обе модели получают дополненный вектор). Пиннинг-тест меняется
  осознанно, `MATH_ENGINE.md §6.2` — вместе с кодом.
- **B (лучше, +1 день):** сценарии, названные по историческим эпизодам, — исторический
  прогон фактических доходностей факторных ETF за окно эпизода (Q2 2022:
  2022-04-01…2022-06-30) из той же матрицы цен; гипотетические — параметрические с A.
  Пятилетнее окно покрывает Q2 2022 до ≈апреля 2027 — дальше эпизод нужно хранить отдельно.

### 2.5 🟠 Размер продажи взят у сделки противоположного знака

### 2.6 🟡 Зона продажи ниже рынка, стоп внутри зоны

**Симптом.** FTNT 178.76: «продавать 162.58–178.76», стоп 172.39.

инварианты Sell: `цена ≤ низ зоны ≤ верх зоны`, `стоп < цены`. `MATH_ENGINE.md §14a`.
