## 1. Вердикт: одним ответом нельзя, потому что ответ зависит от книги

| Класс портфеля | Достаточно? | Чем ограничено |
|---|---|---|
| **US-акции и ETF из ликвидного набора** | ✅ **да** | ничем: факторы 10/10, бенчмарки 3/3, прокси 5/5 |
| US-бумага вне рабочего набора (~800 из 11 842) | 🟡 **условно** | лечится добором из архива; до добора `C-8` режет по стоимости |
| Крипта (`BTC.V`, `ETH.V`, `SOL.V`, `BNB.V`) | ✅ да | но выходные грузить ОБЯЗАТЕЛЬНО: календарь 7/7 |
| Класс акции (`BRK.B`) | ✅ да | форма `brk-b.us`, ловушка №7 учтена в `stooq_symbols` |
| **KASE / бумаги в тенге** | ⛔ **нет** | `KZTK.KZ`, `KMGZ.KZ`, `KEGC.KZ` у Stooq ОТСУТСТВУЮТ |
| **GDR на Лондоне** (`KAP`, `HSBK`) | 🟡 не проверено | нужен пакет `d_world_txt`, суффикс `.UK`, замера нет |
| **AIX-ноты, структурные продукты** | ⛔ нет | нет ни у Stooq, ни у кого; у брокера была ЦЕНА, здесь её нет |
| **Облигации по ISIN** (`KZ…`, `US…`) | ⛔ нет | тот же случай: у Freedom работала ветка «цена брокера» |

🔴 **Главное следствие.** Для целевой аудитории продукта — казахстанского
инвестора — Stooq покрывает **американскую часть книги и только её**. Замер
`STOOQ_CONVENTION §3.7`: группа C (KZ/IL) — **1 попадание из 6, и оно ложное**
(`KSPI.KZ` «нашёлся» как `KSPI.US`, а это ADR на Nasdaq — другая бумага, другая
валюта, другая ликвидность).

## 2. Что брокер даёт, а Stooq не даёт в принципе

Семь позиций. Первая — не про цены вовсе, и она же самая крупная.

### 2.1 Состав портфеля

Freedom API отдаёт позиции, количество, цену покупки и текущую цену
(`freedom_portfolio/client.py` → `broker_api._to_dataframe`). Stooq не отдаёт
ничего из этого и не может: это база КОТИРОВОК, а не брокерский счёт.

**Замена — ручной ввод**, и она меняет не данные, а **ответственность**:

| | Freedom | Manual |
|---|---|---|
| Кто отвечает за состав | брокер | пользователь |
| Опечатка в количестве | невозможна | **не ловится ничем** |
| Забытая позиция | невозможна | не ловится ничем |

`C-10` проверяет арифметику весов, `C-8` — покрытие по стоимости. Ни один
чекер не умеет заметить, что вместо 100 акций введено 1000: книга при этом
внутренне непротиворечива. Это не дефект реализации — это цена ручного ввода,
и её надо называть вслух, а не прятать за словом «паритет».

### 2.2 `Broker_Current_Price` — фолбэк, которого у ручного пути нет

Приоритет назначения цены (`engine/portfolio_manager.py:505-565`):

```
(1) кэш                        → 1.0
(2) своя ценовая история       → последний бар матрицы
(3) ЦЕНА БРОКЕРА (mkt_price)   → фолбэк для бумаг без истории
(4) цена покупки               → только если бумага ПРОКСИРОВАНА
```

У ручного портфеля `Broker_Current_Price = None` **намеренно**
(`manual_portfolio.py:162`) — ветки (3) не существует. Отсюда следствие,
которого нет ни в одном обещании паритета:

> 🔴 Бумага **без истории у Stooq и без прокси** не получает цену вовсе,
> `dropna(subset=['Current_Price'])` выбрасывает строку, и её стоимость
> **исчезает из NAV**.

Ловится это `C-8` (доля непокрытой стоимости) и в `STRICT` даёт `BLOCK` — то
есть пользователь получит честный отказ, а не тихо усечённый портфель. Но
сравнение «тот же отчёт» здесь ломается: у Freedom книга с AIX-нотой строится
по цене брокера, у Stooq — не строится совсем.

### 2.3 Класс инструмента: факт брокера против эвристики по тикеру

| | Freedom | Manual |
|---|---|---|
| Источник | поля `t` / `k` ответа Tradernet | форма тикера |
| Код | `asset_taxonomy.from_freedom_metadata` (приоритет 1 — поле `t`) | приоритет 2 — эвристики |

`from_freedom_metadata` прямо объявляет порядок: «broker `t` field
(authoritative for Stock/Bond)», и только при его отсутствии — «ticker shape
heuristics». У ручного ввода первый приоритет пуст ВСЕГДА.

Где это видно в отчёте: доли классов активов в мандатной панели, пиллар **C**
(Credit не применяется к не-долговым), `Asset_Type` в таблице позиций.
Для `AAPL.US` разницы нет; для облигации, которую эвристика не знает, — есть.

### 2.4 Свежесть цены: внутридневная против T-1

Freedom отдаёт `mkt_price` на момент запроса. Stooq отдаёт последний дневной
бар, и только тот, который **оператор успел залить**.

Для риск-метрик это несущественно: волатильность, Sharpe, VaR, Euler считаются
на дневных лог-доходностях, и сдвиг окна на день их не меняет содержательно.
Для **стоимости портфеля** — существенно: NAV в отчёте будет отличаться от
цифры в брокерском приложении на дневное движение рынка.

### 2.5 Валюта позиции

Freedom сообщает валюту каждой позиции (`p.curr`). У Stooq валюта выводится из
рынка (`instruments.currency`, `market_calendar.currency_of`), а у ручного
ввода дополнительно спрашивается у пользователя, причём для `GBX` —
**обязательно явно** (`manual_portfolio.AMBIGUOUS_CURRENCIES`): ошибка в 100 раз
не даёт ни одного видимого признака.

Для `.US` совпадение полное. Расхождение начинается там, где начинается мир.

### 2.6 Корпоративные события

| Ось | Freedom | Stooq |
|---|---|---|
| Сплиты | объявлено рассуждением | ✅ **ИЗМЕРЕНО**: 7 из 7 событий без ступеньки → ряд скорректирован |
| Дивиденды | не измерено | не измерено |

🔴 Здесь Stooq **документирован лучше**, а не хуже: у Tradernet конвенция
объявлена рассуждением «дивиденды не корректируются нигде в коде»
(`price_providers.TradernetProvider`), у Stooq ось сплитов закрыта замером
оператора (`stooq_ingest.py:57-65`). Ось дивидендов открыта у обоих одинаково.

### 2.7 Что делать с бумагой, которой нет в рабочем наборе

Бутстрап отбирает ~800 ликвидных из 11 842 по измеренным признакам. Бумага
пользователя может не попасть туда **на законных основаниях** (мало оборота,
короткая история). Лечится `backfill` из локального архива — то есть сегодня
это операция на машине оператора, недоступная из облака.

Это ограничение прямо влияет на план бота-загрузчика: файл истории ОДНОЙ бумаги
(`aapl.us.txt`, сотни КБ) через Telegram проходит, архив целиком (0.84 ГБ) — нет.

## 3. Что от источника цен не зависит вообще

Проверено сканом: **ни один расчётный модуль `finance/` не делает сетевых
вызовов**. Внешний мир входит через адаптеры, и пять из шести к цене отношения
не имеют:

| Данные | Модуль | Зависит от источника цен? |
|---|---|---|
| Фундаментал (ROE, маржа, долг, Altman-Z, Piotroski-F) | `sec_edgar.py` | ❌ нет — тянется по CIK |
| Макро-пак (10Y−2Y, HY OAS, VIX, breakeven, безработица, ВВП) | `services/macro_data.py` | ❌ нет — FRED |
| Курс USD/KZT | `services/fx_feed.py` | ❌ нет — FRED `DEXKZUS` |
| Кредитный прокси | `cds_feed.py` | ❌ нет — FRED |
| Банковская аналитика (цитаты GS/MS/JPM) | `agent/rag_engine.py` | ❌ нет — ChromaDB |
| ИИ-нарратив | `ai_narrative.py` | ❌ нет — и **ни одного числа не считает** |

Вся математика — факторные беты, Euler-разложение, CVaR с bootstrap, 4-Pillar,
режим, стресс, Black-Litterman, риск-индекс 0–100 — считается **в проекте** и
получает от источника ровно одно: матрицу цен закрытия.

**Отсюда главный технический вывод:** источник влияет на отчёт через ОДИН вход.
Если матрица покрыта, всё остальное совпадает по построению — и это уже
доказано тестами (§5).

## 4. Где Stooq даёт БОЛЬШЕ, чем используется сегодня

| Что | Состояние |
|---|---|
| **Объёмы торгов** | `daily_bars.volume` заполняется ingest-ом и лежит в базе. `technicals._volume_confirm` умеет их читать, но `volume_frame = None` (`portfolio_manager.py:1281`, «wired in a later phase») — сигнал выключен **у обоих** путей |
| **OHLC** | база хранит open/high/low; `action_plan` считает ATR по Wilder RMA и сегодня получает только close |
| **Точность** | замер: 6 значащих цифр даже на микроценах (`BTT.V` = 0.000000262737) — доходности считаются без потерь |
| **Идемпотентность** | 8 467 общих бумаг двух редакций одного среза — **0 расхождений в close** |
| **Шов «архив ↔ дельта»** | совпадение до последнего знака на всех живых бумагах (`verify-seam`) |

То есть путь Stooq **ближе к включению volume-confirm и честного ATR**, чем
брокерский: данные уже в базе, нужен только провод.

## 5. Что доказано тестами — и чего они НЕ доказывают

Это самый важный раздел, потому что здесь легче всего обмануться.

| Тест | Что доказывает |
|---|---|
| `test_manual_freedom_parity` | `results{}` — 36 ключей движка — совпадают, кроме двух, которые обязаны различаться |
| `test_phase50_report_layer_parity` | состав ключей design-data, числа риска, число строк полосы качества совпадают для обоих тиров |

🔴 **Оба теста строят два отчёта НА ОДНИХ ЦЕНАХ.** Они доказывают, что
конвейер не ветвится по источнику, — и это ценно: значит расхождение может
прийти только из данных, а не из кода. Но они **не доказывают**, что цена
`AAPL.US` у Stooq равна цене `AAPL.US` у Tradernet.

Это ровно **пункт 10 чек-листа оператора**, который остаётся открытым: сверка
10 бумаг против Tradernet по трём порогам (`PHASE_09 §4.1`).

> **Паритет кода ≠ паритет данных.** Первый доказан. Второй не измерен.

## 6. Пять отличий, которые останутся навсегда

Даже когда все открытые пункты закроются:

1. **NAV на T-1**, а не внутридневной.
2. **Нет цены брокера как фолбэка** — бумага без истории выпадает, а не оценивается.
3. **Класс инструмента по эвристике**, а не по полю брокера.
4. **Профиль чекеров `STRICT` против `LEGACY`** — по одним и тем же данным ручной
   путь заблокирует отчёт там, где брокерский его отдаст. Например `C-1`: потеря
   ЛЮБОГО факторного ETF в `STRICT` даёт `BLOCK`, в `LEGACY` — `DEGRADE`
   (`data_checks.py:428-441`). Это осознанно строже, а не хуже.
5. **Провенанс обязан отличаться** — строка CoVe «Цены и история активов» не
   вправе быть подписана `Tradernet (Freedom Broker)` у не-клиента брокера
   (I-12). Тест это ТРЕБУЕТ, а не допускает.

Первые три — потери. Четвёртое и пятое — не потери, а другое обещание
пользователю; продавать их как «то же самое» нельзя.

## 7. Итог

**«Точно такие же отчёты» — да, для американской книги из ликвидных бумаг,
с точностью до цены дня и класса инструмента.**

Формально: конвейер идентичен (доказано), все внешние данные кроме цен
идентичны (проверено сканом), покрытие факторной модели полное (замерено
10/10 и 3/3). Отличия сосредоточены в трёх местах — свежесть цены, отсутствие
брокерского фолбэка, эвристика класса — и все три поддаются описанию одной
строкой в отчёте.

**Нет — для казахстанской книги.** И это не «пока нет», а «нет у этого
источника»: KASE в выгрузке Stooq отсутствует. Варианта два — платный источник
(`PHASE_10` EODHD) либо честный отказ по бумаге. Третьего нет, и подмена
`KSPI.KZ` → `KSPI.US` третьим вариантом не является: это другая бумага.
