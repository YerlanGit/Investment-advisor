## 2. Эндпоинт

```
https://stooq.com/q/d/l/?s={ticker}&d1={YYYYMMDD}&d2={YYYYMMDD}&i=d&apikey={KEY}
```

| Параметр | Значение |
|---|---|
| `s` | тикер, нижний регистр: `aapl.us`, `spy.us` |
| `d1`, `d2` | границы диапазона, `YYYYMMDD` |
| `i` | `d` — дневной интервал |
| `apikey` | **требуется** |
| `c` | семантика не документирована; **не передавать**, пока Фаза 8 не зафиксирует |

Успешный ответ — CSV `Date,Open,High,Low,Close,Volume`.

**Формат отказа — HTTP 200 с не-CSV телом.** Это наблюдаемое поведение, а не гипотеза:
инструкция про капчу при проблеме с ключом и `Exceeded the daily hits limit` при
исчерпании квоты приходят с кодом 200. Поэтому чекер A-1 (Фаза 3) — обязательный,
а не желательный, а `pd.read_csv(url)` запрещён категорически (Т-1).

## 3. Требования безопасности

| # | Требование | Обоснование |
|---|---|---|
| **S-1** | Тикер приводится к нижнему регистру → валидируется по whitelist `^[a-z0-9][a-z0-9._-]{0,19}$` → `urllib.parse.quote`. Отказ → `failed[ticker]`, запрос **не отправляется** | Тикер приходит из пользовательского ввода: без этого возможна инъекция параметров (`&s=`, перевод строки) и SSRF |
| **S-2** | Только `https://`, проверка сертификата включена, редиректы запрещены (`allow_redirects=False`); любой 3xx → отказ | Редирект на капчу/логин — штатное поведение Stooq при проблемах с ключом |
| **S-3** | `requests` с `timeout=(5, 15)`, `stream=True`, жёсткий потолок тела 5 МБ; превышение → обрыв и `failed` | Ответ неизвестного размера в процесс с лимитом 2 GiB, где `/tmp` — RAM |
| **S-4** | **Никогда** `pd.read_csv(url)`. Только: скачать → провалидировать (блок A) → `pd.read_csv(io.StringIO(text))` | Прямой `read_csv(url)` не имеет ни таймаута, ни лимита размера и парсит страницу ошибки как данные |
| **S-5** | `apikey` маскируется в логах (`apikey=***`); ключ не попадает в текст исключения | I-8 |
| **S-6** | Ограничение параллелизма — **свой** параметр провайдера, независимый от `max_workers=6` Tradernet. Старт **2**, с джиттером между запросами | У Stooq нет ни опубликованных лимитов, ни SLA. Агрессивный параллелизм = бан IP Cloud Run, то есть отключение сервиса целиком (Т-7) |
| **S-7** | Ответы кэшируются с провайдером в ключе (Фаза 1), TTL как сейчас | Снижает нагрузку на источник без публичной квоты |
| **S-8** | Circuit breaker: N подряд отказов → провайдер недоступен на T минут, запросы не шлются | Защита от блокировки IP и от долбёжки мёртвого эндпоинта |

### 3.1 Порядок операций в S-1 (уточнение)

Задание пишет «валидируется до сборки URL», но не фиксирует момент приведения регистра.
Порядок обязателен именно такой:

```
"AAPL.US"  →  lower()  →  "aapl.us"  →  whitelist  →  quote()  →  URL
```

Валидация **после** `lower()`: whitelist начинается с `[a-z0-9]`, и любой тикер
в верхнем регистре отвергался бы как «невалидный», хотя проблема только в регистре.
Валидация **до** `quote()`: `quote()` экранирует опасные символы, и проверка после него
пропустит `%26s%3Devil` — экранированный, но семантически всё ещё инъекция.

### 3.2 Про юридический статус — честно

Stooq — публичный бесплатный сайт без опубликованного коммерческого API-контракта;
условия использования для программного доступа в рамках платного продукта
**не проверялись и этой фазой не устанавливаются**. Практический вывод: Stooq пригоден,
пока проект малого масштаба, и это одна из причин, почему §8 задания фиксирует переход
на лицензированный источник, а не оставляет Stooq навсегда. Отдельный запрос
в Stooq о допустимости коммерческого использования — дешёвый шаг, снимающий
неопределённость; рекомендуется до включения флага в проде.

## 4. Переключение источника — не по умолчанию

`manual` **остаётся на Tradernet** после этой фазы. Переключение — отдельное решение,
принимаемое только после сверки:

### 4.1 Сверка перед переключением

10 тикеров, покрытых обоими источниками: `SPY.US`, `QQQ.US`, `AGG.US`, `IEF.US`, `EEM.US`,
`EMB.US`, `DBC.US`, `AAPL.US`, `MTUM.US`, `URTH.US`.

| Метрика | Порог |
|---|---|
| `max\|Δclose\| / close` | ≤ 0.5% |
| Корреляция дневных доходностей | ≥ 0.999 |
| Разница годовой волатильности | ≤ 0.5 п.п. |
| Расхождения в календаре торговых дней | зафиксировать число |

Затем `analyze_all` на одном портфеле по обоим источникам: Risk Index, CVaR 95,
топ-3 вклада TRC, факторные беты. **Провал любого порога = переключения нет**,
результат идёт в отчёт.

Корреляция доходностей важнее совпадения уровней: именно доходности идут в ковариацию
и именно они выявляют разницу конвенций — дивидендная составляющая даёт систематический
дрейф при почти совпадающих уровнях цен.

### 4.2 Что меняется для пользователя

Переключение сдвинет числа в ручных отчётах ровно на разницу источников. Поэтому:

- флаг `PRICE_PROVIDER_MANUAL` переключается **без передеплоя** (гейт «Откат» §10);
- сверка §4.1 прикладывается к решению;
- если сверка не проходит — `manual` остаётся на Tradernet, и это **нормальный исход**,
  а не провал фазы. Провайдер при этом остаётся в коде как резерв на случай сбоя Tradernet
  (исходная задача `ROADMAP_DATA_RESILIENCE.md §1`).

## 5. `ChainProvider` и запрет смешивания (I-7)

`ChainProvider(primary, fallback)` добирает у резерва тикеры, которые основной источник
не отдал за N ретраев. Жёсткие правила:

1. Fallback **только целиком по тикеру**, никогда по-дневно;
2. Если конвенции провайдеров различаются — смешивание **запрещено**: цепочка
   отказывает целиком, а не отдаёт матрицу из двух конвенций (`test_mixed_convention_rejected`);
3. Источник фиксируется **в каждой колонке** (`ProviderResult.source`) и попадает
   в CoVe (Фаза 6, §4);
4. Флаг `PRICE_PROVIDER_CHAIN=off` по умолчанию — цепочка включается только после сверки §4.1.

### 6.1 Про Т-3 отдельно

`_detect_and_adjust_splits` (`history.py:488`) снапит подразумеваемое отношение
к ближайшему целому `2..50` **или обратному к нему** (строка 525), при пороге
`|log return| > log(1.5)` (485). Удвоение цены за день даёт `raw_ratio ≈ 0.5`,
что снапится к `1/2` и обрабатывается как **обратный сплит** — прошлые цены умножаются вдвое.

`BTC-USD` есть в демо-портфеле (`broker_api.py:365`), а криптоактивы двигаются на десятки
процентов за сессию штатно. Тест обязателен и должен падать на текущей эвристике,
если её не защитить (например, исключением тикеров с `Asset_Type == "Крипто"`
из эвристического слоя). **Решение по защите принимается в этой фазе, но касается
`history.py`, а не Stooq** — то есть затрагивает и путь `freedom`; поэтому изменение
поведения фиксируется снапшот-тестом I-5 и строкой в `docs/audit/AUDIT.md`.
