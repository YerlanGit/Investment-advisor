## 0. Что изменилось для этого проекта в раунде 12.08

Аудит 12.08 шёл по отчётам, собранным через **Freedom API**, а не через ручной
ввод, поэтому прямых находок по `manual` он не дал. Но три правки общего слоя
касаются ручного пути напрямую — их надо учитывать при работе над Фазой 09:

1. **Валютный слой CoVe стал честным (A-3).** Пустой список конверсий больше не
   печатается как «конверсия не требуется»: при находке C-11 строка уходит в
   `warn` и называет валюту. Для `manual` это критично сильнее, чем для брокера:
   пользователь вводит суммы в ₸ руками, и отсутствие курса там — штатный исход,
   а не край. **Ожидание:** ручной портфель с тенговыми строками при недоступном
   FX обязан показывать эту строку жёлтой.
2. **Доля IT нормируется на инвестированный капитал (A-6).** Ручная книга легко
   бывает без кэша вовсе — тогда знаменатель 1.0 и поведение прежнее. Проверить
   на фикстуре `results_golden_manual.json` (обновлена в раунде).
3. **Причина у нулевого количества (A-7).** У `manual` цены приходят от Stooq и
   бывают грубее брокерских, поэтому строк с «сделка меньше одной акции» будет
   БОЛЬШЕ, чем на брокерском пути. Ветка уже есть — отдельной работы не требует.

## 2. Задачи

### 🔴 MP-09-pre · молчаливая потеря позиции (предусловие, блокирует включение)

**Проблема измерена, не предположена** (`ЧК-08.2`): бумага без ценового ряда
исчезает из портфеля МОЛЧА — позиция на 70 % книги, `total_value` $20 641 вместо
$71 450, и **все чекеры молчат**, потому что C-8 считает покрытие по уже выжившим
строкам.

**Требование:** бумага без ряда остаётся в книге по цене покупки, а непокрытая
стоимость доезжает до C-8.
**Спецификация уже существует падающим тестом:**
`test_uncovered_value_reaches_c8_SPEC_FOR_MP09`.
**Оценка:** 1 день. **Блокирует:** MP-09, MP-06.

### ⛔ ЧК-08.1 · замер покрытия Stooq (заблокирован окружением)

Готово всё, кроме сети: `scripts/stooq_coverage_probe.py` собирает универсум ИЗ
КОДА (34 бумаги, 6 групп), перебирает формы символа, отличает тело квоты от
отсутствия бумаги. `stooq.com` отдаёт 403 на CONNECT из агентского окружения,
ключ добывается через капчу. **Оператору — одна команда**, регламент в
`OPERATOR_STOOQ.md`.

🔴 Список `§2.5` плана устарел втрое: 4 KZ-бумаги против 6 в словаре, 3 события
сплитов против 7, `vwo.us` назван нужным при мёртвом `EM_EQUITY_FALLBACK`.

### ⛔ ЧК-08.5-4 · `stooq_provider.py` (отложен ОСОЗНАННО)

Протокол Фазы 02 требует объявить конвенцию для каждого тикера. Конвенция Stooq
**не измерена**, а `SPLIT_ADJUSTED` «по аналогии» дал бы ДВОЙНУЮ корректировку уже
скорректированного ряда. База хранит `convention='unmeasured'`, и это запинено
тестом. **Зависит от:** ЧК-08.1.

### 🔴 MP-09 · `StooqProvider` — без него ручной ввод не работает

| Чекпойнт | Требование |
|---|---|
| ЧК-09.1 | Провайдер реализует протокол Фазы 02 и проходит его тесты **без правок протокола** |
| ЧК-09.2 | S-1…S-8: лимиты, таймауты, санитизация тикера в URL, кэш Фазы 01 |
| ЧК-09.3 | Отказ провайдера НЕ роняет отчёт брокерского пути (изоляция источников) |
| ЧК-09.4 | `provider_for_source("manual")` возвращает Stooq, а не Tradernet — тест ПРЯМОЙ (I-12 это юридическая граница, а не стилистика) |

**Оценка:** 2.5 дня. **Зависит от:** ЧК-08.5-4, MP-09-pre.

### 🟠 MP-06 · включение `source='manual'` в проде

| Чекпойнт | Требование |
|---|---|
| ЧК-06.1 | `data_lineage` называет источник «ручной ввод» и провайдера цен ОТДЕЛЬНО |
| ЧК-06.2 | Тариф и списание идентичны брокерскому пути (токен — после доставки) |
| ЧК-06.3 | `MANUAL_PORTFOLIO_ENABLED=off` убирает пункт меню **И** не регистрирует хендлеры — тест на оба следствия |
| ЧК-06.4 | Живой прогон ручного портфеля с отчётом, как для брокерского (`§−51`) |
| **ЧК-06.5** *(новое, из раунда 12.08)* | Ручная книга с тенговыми строками при недоступном FX показывает **жёлтую** строку валютного слоя, а не зелёную «конверсия не требуется» (A-3) |

**Зависит от:** MP-05 ✅ **и** MP-09.

### 🟡 MP-06-guard · флаг off не должен запирать пользователя

**Сегодня дефекта НЕТ** — проверено по коду 12.08: ветка отказа в `cb_confirm`
отдаёт `kb_connect_choice()`, то есть выход у пользователя есть. Риск —
**будущий**: `_resolve_portfolio_source` возвращает `manual`, не спрашивая флага, и
нынешняя ветка-отказ исчезнет вместе с заглушкой в момент проводки источника в
расчёт. **Требование:** при `MANUAL_PORTFOLIO_ENABLED=off` пользователь с
сохранённым режимом `manual` обязан получить ВЫБОР источника, а не отказ без выхода.
**Делать вместе с MP-06,** не раньше — иначе гард охраняет несуществующий путь.

### 🟢 A-76.2 · I-9 держится на волатильности `MemoryStorage`

У `msg_manual_input` гарда флага нет; сегодня безопасно только потому, что смена
флага = новая ревизия = пустое FSM-хранилище. Если хранилище станет персистентным
(Redis), выключение флага перестанет выключать фичу. **Записано как латентная
связь, а не как задача:** чинить вместе с переездом хранилища.
