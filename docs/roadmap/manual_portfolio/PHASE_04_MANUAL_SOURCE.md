## 1. Цель

Модуль `src/finance/manual_portfolio.py`, превращающий текст пользователя
в **тот же самый** `DataFrame`, который отдаёт `FreedomConnector` — так, чтобы
`analyze_all()` отработал на ручном портфеле без единой правки движка (I-2).

Модуль **не импортирует `tg_bot`** и ничего не знает про Telegram: на входе строка,
на выходе `DataFrame` + отчёт о разборе. Это делает его тестируемым офлайн
и переиспользуемым в Фазе 7 (CSV/XLSX).

## 2. Целевой контракт DataFrame

Восстановлен по `broker_api.FreedomConnector._to_dataframe` (строки 287-357) — воспроизводить
надо ровно его, включая порядок колонок.

```python
columns = ["Ticker", "Quantity", "Purchase_Price", "Broker_Current_Price",
           "Asset_Type", "Raw_Ticker"]
```

Рисковая позиция:

```python
{"Ticker": "AAPL", "Quantity": 10.0, "Purchase_Price": 150.50,
 "Broker_Current_Price": None,          # цену даст провайдер — приоритет (2)
 "Asset_Type": _classify_instrument("AAPL"),
 "Raw_Ticker": "AAPL.US"}                # как ввёл пользователь
```

Денежная строка — дословно как у брокера (`broker_api.py:343-350`):

```python
{"Ticker": "USD", "Quantity": 5000.0, "Purchase_Price": 1.0,
 "Broker_Current_Price": 1.0, "Asset_Type": "Кэш", "Raw_Ticker": "USD"}
```

**Три детали, которые легко упустить:**

1. **`Ticker` без биржевого суффикса.** Брокерский путь прогоняет тикер через
   `_strip_exchange_suffix` (`AAPL.US` → `AAPL`, строка 297), а полный тикер кладёт
   в `Raw_Ticker`. Ручной ввод обязан делать то же: иначе `resolve_tickers` получит
   `AAPL.US` вместо `AAPL` и пойдёт другой веткой (`'.' in t_str` → passthrough,
   строка 711 — вместо ветки 7 `f"{t}.US"`). Результат тот же, но полагаться на это нельзя:
   для `BRK.B` ветки расходятся.
2. **`Broker_Current_Price = None` у рисковых позиций.** Ручной ввод не знает рыночной
   цены. `None` заставляет `analyze_all` взять цену из ценовой матрицы (приоритет 2,
   строка 1686) — правильное поведение. Подставлять сюда `Purchase_Price` **нельзя**:
   это включит ветку `broker_priced_only` (1689-1692), позиция вылетит из факторной модели,
   а PnL станет тождественно нулевым.
3. **`Asset_Class` / `Asset_Class_Label` не нужны.** Брокерский путь их формирует
   (строки 329-330), но конструктор `pd.DataFrame(rows, columns=[...])` их **отбрасывает** —
   в списке колонок их нет. Ручной ввод их не создаёт: паритет сохраняется.

**Маркеры `df.attrs`.** Ручной портфель — реальный, поэтому **ни один** из
`_ramp_is_mock` / `_ramp_is_fallback` не ставится (иначе сработает гейт
`analyze_all:1625-1636` и `tg_bot:2117-2134`). Ставится один новый:
`df.attrs["_ramp_source"] = "manual"` — по образцу существующего `"demo"` (`broker_api.py:209`).

## 3. Текстовый формат

Строго по §3.2 задания. Одна позиция — одна строка, разделитель — пробел, табуляция,
запятая или точка с запятой; единообразие внутри строки не требуется.

```
ТИКЕР  КОЛИЧЕСТВО  ЦЕНА_ПОКУПКИ
CASH:USD  5000                      # кэш — два поля, цена = 1.0 по определению
```

| Правило | Поведение |
|---|---|
| Строки с `#` и пустые | Игнорируются |
| Регистр тикера | Приводится к верхнему |
| Десятичный разделитель | Точка и запятая равнозначны: `150,50` = `150.50` |
| Разделители разрядов | Пробел и `_` внутри числа удаляются: `2 500 000` = `2500000` |
| `CASH:XXX` | → `Ticker=XXX`, `Purchase_Price=1.0`, `Asset_Type="Кэш"` |
| Голая валюта из `NON_RISK_ASSETS` (`USD 5000`) | Принимается как кэш, эквивалент `CASH:USD` |
| Цена у кэша указана и ≠ 1.0 | Ошибка строки с пояснением |
| Дубликат тикера | Суммируются; цена покупки — средневзвешенная по количеству; результат склейки показывается пользователю |
| Отрицательные и нулевые количество/цена | Ошибка строки с номером |
| Тикер не прошёл `resolve_tickers()` или не дал истории | Строка помечается и **исключается**, не подставляется |

**Короткие продажи не поддерживаются.** Движок, стресс-тесты и Black-Litterman рассчитаны
на длинные позиции; отрицательное количество даёт отрицательный вес, а `composite_risk_score`
и Euler-декомпозиция на таких весах молча выдают бессмыслицу. Явный отказ с пояснением.

### 3.1 Неоднозначности формата, не покрытые заданием

Разобрать явно, иначе они станут дефектами:

| Случай | Решение |
|---|---|
| Два поля, но тикер **не** валюта (`AAPL 10`) | Ошибка строки: «не указана цена покупки». Не догадываться |
| `CASH 5000` — `CASH` есть в `NON_RISK_ASSETS`, но это не валюта | Ошибка: «укажите валюту, например `CASH:USD`». Псевдо-тикер `CASH` от брокера не приходит никогда (`acc` даёт коды валют) |
| Четыре и более полей | Ошибка строки с указанием, сколько полей ожидалось |
| Разделитель разрядов **и** десятичная запятая: `2 500,50` | Пробелы убираются, запятая → точка → `2500.50`. Порядок операций важен |
| Запятая как разделитель полей **и** как десятичная: `AAPL,10,150,50` | **Неразрешимо.** Ошибка строки с требованием использовать пробел или `;` при десятичной запятой. Угадывать нельзя — цена «150.50» и цена «150» с лишним полем неразличимы |
| Дубликат кэша в одной валюте (`CASH:USD` дважды) | Суммируется, как и тикеры; средневзвешенная цена не считается — она тождественно 1.0 |
| Дубликаты с разной формой (`AAPL` и `AAPL.US`) | Склеиваются **после** нормализации `Ticker`, то есть считаются одной позицией |

### 3.2 Валидация тикера — два разных слоя (ловушка Т-2)

Задание в одном месте запрещает свою регулярку (Т-2), в другом требует whitelist (S-1).
Противоречия нет — это разные слои, и путать их нельзя:

- **Слой ввода** (эта фаза): проверяется только то, что строка непуста, не длиннее
  32 символов и не содержит управляющих символов/переводов строки. Авторитет
  распознавания — `resolve_tickers()` со всеми семью его правилами (кэш, облигации→прокси,
  AIX→прокси, `TICKER_MAP`, крипто, passthrough, `.US`). Своей биржевой логики здесь нет (Т-4).
- **Слой провайдера** (Фаза 9): whitelist S-1 `^[a-z0-9][a-z0-9._-]{0,19}$` — **после**
  приведения к нижнему регистру и **до** сборки URL, далее `urllib.parse.quote`.

Тикеры `AAPL.US`, `BTC-USD`, `FFSPC0824.AIX` обязаны проходить слой ввода без потерь.

## 4. Разбор → отчёт, а не исключение

```python
@dataclass
class ParsedPosition:
    raw_line:   str
    line_no:    int
    ticker:     str
    quantity:   float
    price:      float
    is_cash:    bool
    currency:   str | None

@dataclass
class ParseReport:
    positions: list[ParsedPosition]
    errors:    list[tuple[int, str]]   # (номер строки, человеческая причина)
    merged:    list[tuple[str, int]]   # склеенные дубликаты: (тикер, сколько строк)
    def to_dataframe(self) -> pd.DataFrame: ...
```

Парсер **никогда не бросает** на пользовательском вводе: любая проблема — запись
в `errors` с номером строки. Экран подтверждения (Фаза 5) показывает и принятое,
и отвергнутое — пользователь видит, что именно потерялось.

## 5. Кэш в валюте ≠ базовой — самый тяжёлый пункт фазы

### 5.1 Дефект

Найдено при разборе (`README.md §3`, F-2), заданием не обнаружено.
`analyze_all` пиннит цену кэша безусловно:

```python
# investment_logic.py:1681-1683
if orig_str in self.engine.NON_RISK_ASSETS:
    current_prices[orig] = 1.0
    continue
```

FX применяется к **матрице цен** (`_apply_fx_conversion`, строка 774), а строки кэша
до неё не доходят — они не тикеры. Значит `CASH:KZT 2500000` из примера §3.2 задания
входит в портфель как **2 500 000 у.е.**: при книге акций на $10 000 тенговый остаток
(≈ $4 800) получает вес 99.6% вместо ≈32%, и вместе с ним уезжают TRC, CVaR, беты,
Black-Litterman и композитный риск-индекс. Ни одного визуального признака ошибки.

Тот же путь проходит тенговый остаток с брокерского счёта (`broker_api.py:336-351`),
то есть **дефект существует и без этой ветки** — на freedom-пути, у любого KZ-клиента.

### 5.2 Решение в границах I-2

`analyze_all` заморожен, поэтому конвертация выполняется **до** него, в слое `manual`:

```
CASH:KZT 2 500 000
  → курс KZT→USD из services.fx_feed (последнее наблюдение DEXKZUS)
  → {"Ticker": "USD", "Quantity": 4 807.69, "Purchase_Price": 1.0, ...}
  → в CoVe: «Кэш KZT 2 500 000 → USD 4 807.69 по курсу 520.0 на 2026-07-24»
```

Правила:

- базовая валюта — `ReportingCurrency.from_env()`, та же, что у движка
  (`investment_logic.py:478-483`), рассинхрон недопустим;
- курс берётся тем же `services.fx_feed`, что и для цен, — один источник, один лаг;
- **строки кэша в разных валютах после конвертации схлопываются в одну** строку
  базовой валюты (иначе в портфеле окажутся `USD` и `USD` дважды);
- курс и дата наблюдения обязательно уходят в CoVe: конвертация не должна быть невидимой.

### 5.3 Валюта без курса

`fx_feed` регистрирует `USD↔KZT` (`DEXKZUS`) и `GBP↔USD` (`DEXUSUK`) — строки 54-63.
**Задание утверждает, что поддерживается только USD↔KZT (ошибка E-3), но вывод
от этого не меняется:** для `EUR` и `RUB`, которые есть в `NON_RISK_ASSETS`, курса нет.

Поведение — по §3.5 задания, без послаблений:

1. На экране подтверждения — явное предупреждение с названием валюты;
2. Пользователь выбирает: исключить позицию или продолжить без неё;
3. В обоих случаях — строка DEGRADE (C-11) в CoVe;
4. **Молчаливое `1.0` не остаётся ни на одном пути** (Т-5).

Расширять `FRED_FX_SERIES` парами EUR/RUB — вне объёма фазы: это отдельное решение
про источник и его надёжность, а не часть ручного ввода.

### 5.4 Что делать с freedom-путём

Дефект F-2 существует независимо. Варианты:

- **(a)** починить в этой же ветке — перенести конвертацию кэша в общий слой
  до `analyze_all` для обоих источников. Технически чисто, но расширяет объём
  и требует пересчёта снапшотов I-5 (числа freedom-отчётов с тенговым кэшем **изменятся** —
  в правильную сторону, но изменятся);
- **(b)** отдельным PR после ветки.

**Рекомендация — (b)**, и строка в `docs/audit/AUDIT.md` **немедленно**, в этой фазе:
иначе находка растворится. Решение за владельцем продукта (пункт ★ в `README.md §7`).

## 8. Риски

| Риск | Митигация |

| Ручной DataFrame отличается от брокерского в детали, которую не поймали | `test_manual_equals_freedom_same_positions` сравнивает **числа отчёта**, а не форму фрейма, — ловит любое расхождение по последствиям |

| **Тикер есть у Tradernet, но отсутствует у Stooq** (KZ/IL-бумаги, AIX-ноты, крипто) | **Новый риск после решения 2026-07-27**: подставить Tradernet нельзя (I-12), поэтому позиция честно исключается — как любой нераспознанный тикер. | `fx_feed` недоступен (нет `FRED_API_KEY`) → конвертировать нечем | `default_fx_provider()` вернёт `None` (строка 250). Тогда кэш в не-базовой валюте — тот же путь §5.3: исключение с предупреждением, не `1.0` |
