## 🔴 0. Блокировки — прочитать до планирования

Эта фаза **не выполняется агентом и не выполняется в CI**. Два независимых препятствия:

1. **Ключ добывается человеком через капчу.** По §2.2 задания эндпоинт вместо CSV
   возвращает инструкцию: открыть `https://stooq.com/q/d/?s={ticker}&get_apikey`,
   ввести капчу, скопировать ссылку с `apikey`. Это принципиально не автоматизируется.
2. **Сетевая политика окружения не пускает к `stooq.com`.** Проверено прямым обращением
   27.07.2026: агентский прокси отвечает `403` на CONNECT (тот же ответ на `tradernet.com`
   и `tradernet.kz`). Ни проверить эндпоинт, ни выполнить процедуру §2.5 отсюда нельзя.

**Что нужно от оператора, чтобы фаза стартовала:**

- [ ] `STOOQ_API_KEY` получен вручную и положен в Secret Manager — **день 1 проекта**
- [ ] Процедура §2 ниже выполнена в окружении с доступом к `stooq.com`
- [ ] CSV-выгрузки контрольных бумаг сохранены как фикстуры для Фазы 9

## 1. Зачем процедура вообще нужна

Наблюдение «close на stooq.com совпадает с терминалом Bloomberg» — весомый аргумент
за качество источника и принято как основание выбрать Stooq. Но оно устанавливает меньше,
чем кажется:

- совпадение **текущих уровней цен** подтверждает корректность котировок сегодня;
- оно **не подтверждает конвенцию исторических корректировок** — а в ковариацию, беты
  и CVaR идут дневные доходности за 5 лет, то есть поведение ряда **на границах сплитов
  и дивидендов** несколько лет назад;
- у самого Bloomberg историческая серия бывает скорректированной или нет в зависимости
  от настроек (экран DPDF), поэтому «совпадает с Bloomberg» без указания режима
  конвенцию не определяет.

Отсюда: конвенция определяется **эмпирически**, а не назначается по наблюдению.

### 2.1 🔴 Исправление дат относительно задания (ошибка E-4)

Задание (§2.5) указывает **«Сплит 20:1, 2022-06-06, `googl.us`»**. Это неверно:

```python
# src/freedom_portfolio/history.py:50-51
"AMZN.US":  [(date(2022, 6, 6),  20)],
"GOOGL.US": [(date(2022, 7, 18), 20)],
```

`2022-06-06` — дата сплита **AMZN**; у GOOGL это **2022-07-18**.

**Почему это важнее, чем опечатка.** Процедура ищет ступеньку в конкретной дате.
На `2022-06-06` ряд GOOGL ступеньки не имеет **ни при какой конвенции** — там просто
не было события. Исполнитель, следующий заданию буквально, получит «ступеньки нет»
и сделает вывод «ряд скорректирован на сплиты» — независимо от того, что на самом деле
отдаёт Stooq. Ошибочный вывод затем защёлкивается в `PriceConvention` провайдера
и через I-7 расходится по всей ковариации.

Даты в таблице §2 — из `KNOWN_SPLITS`, то есть из кода, а не из задания.

### 2.2 Решение по результату

| Наблюдение | Вывод |
|---|---|
| Ступенек на сплитах нет **и** накопленная доходность SPY совпадает с total return | `PriceConvention.TOTAL_RETURN` |
| Ступенек нет, доходность ниже на дивидендную | `PriceConvention.SPLIT_ADJUSTED` |
| Ступеньки есть | `PriceConvention.RAW` — и тогда слои `KNOWN_SPLITS` + эвристика становятся **обязательными**, а не страховочными |

### 2.5 🔴 Проверка покрытия — решает, возможен ли запуск `manual` вообще

Перенесена сюда из смоука Фазы 9: после решения 2026-07-27 у `manual` нет запасного
источника, поэтому непокрытый тикер — это не «одной колонкой меньше», а вопрос
о жизнеспособности фичи. Узнать это надо **до** написания провайдера и FSM-флоу.

Проверяется наличие ряда **и его длина** (нужно ≥1260 торговых дней, окно `HISTORY_LOOKBACK_DAYS=1825`):

| Группа | Тикеры | Что означает непокрытие |
|---|---|---|
| **A. Факторы (10)** | `spy.us`, `mtum.us`, `vlue.us`, `qual.us`, `iwm.us`, `splv.us`, `dbc.us`, `ief.us`, `eem.us`, `emb.us` | 🔴 **Стоп-фактор.** C-1 в профиле `STRICT` → BLOCK; `manual` не запускается. Решение (исключить фактор из модели) — правка математики, выносится владельцу, исполнителем не принимается |
| **B. Бенчмарки (3)** | `qqq.us`, `agg.us`, `urth.us` | DEGRADE: страдает сравнение с бенчмарком, не факторная модель. Запуск возможен |
| **C. KZ / IL** | `kspi.kz`, `kap.il`, `hsbk.il`, `kztk.kz` | 🟡 KZ-портфели теряют позиции → C-8 (покрытие по стоимости) заблокирует типичный казахстанский портфель. Определяет, для какой аудитории `manual` вообще имеет смысл |
| **D. Крипто** | `btc-usd`, `eth-usd` | 🟡 Крипто-позиции исключаются. `BTC-USD` есть в демо-портфеле |
| **E. Прокси-ETF** | `vwob.us`, `vwo.us`, `bil.us`, `lqd.us`, `hyg.us` | 🟡 Неликвидные бумаги резолвятся в эти прокси (`BOND_PROXIES`, `INSTRUMENT_PROXY_MAP`); без них облигационная часть портфеля не считается. **`vwob.us` критичен**: с 2026-07-29 на него проксируются ВСЕ KZ-бумаги и AIX-ноты (см. `AUDIT.md §−38`) |
| **F. Демо-тикеры** | `aapl.us`, `kspi.kz`, `btc-usd` | Вход для ★-решения «переводить ли демо на Stooq» (`PHASE_00 §3a.3`) |

**Формат тикера Stooq.** Ожидается нижний регистр с суффиксом биржи (`aapl.us`).
Для KZ/IL суффиксы Stooq **не проверены** и могут не совпадать с форматом Tradernet
(`KSPI.KZ`, `KAP.IL`) — соответствие устанавливается эмпирически и фиксируется
таблицей маппинга в артефакте §3. Если маппинг нетривиален, он реализуется в
`StooqProvider` (Фаза 9), а **не** в `resolve_tickers()` — иначе сломается путь `freedom`
(ловушка Т-4: авторитет распознавания один, и он общий для источников).

**Результат проверки — таблица «тикер → есть/нет → длина ряда → формат» в артефакте §3.**
Группа A решает go/no-go запуска; группы C–E определяют, какие портфели `manual`
обслуживает честно, и это надо знать до, а не после первого живого пользователя.

### 2.6 🔴 ЧК-08.2 — судьба непокрытой бумаги (ЗАКРЫТ 2026-08-06)

План ставил вопрос «отказ, прокси или цена покупки» и требовал записать ответ
до реализации. Ответ получен **замером конвейера**, и замер вскрыл дефект.

Книга ручного ввода, где у одной бумаги нет ценового ряда — то есть ровно то,
что даст Stooq для непокрытого тикера:

```
стоимость книги  $71 450, из них непокрытая бумага — $50 000 (70%)
в отчёте         пять бумаг из шести          ← непокрытая ИСЧЕЗЛА
total_value      $20 641                       ← вместо $71 450
чекеры           МОЛЧАТ
```

Лестница цен (`_stage_prices`) знает три ветки: матрица, цена брокера, цена
покупки **для проксированной** бумаги. Обычная бумага без ряда не подходит ни
под одну → `Current_Price = NaN` → строку удаляет `dropna`. C-8 считает
покрытие по стоимости УЖЕ ВЫЖИВШИХ строк, поэтому потерянные 70% для него не
существуют. На брокерском пути дефект маскируется `mkt_price` от Freedom; у
`manual` цены брокера нет по определению.

**Решение:** цена покупки (как у проксированных, `priced_at_cost`) **плюс**
доезд непокрытой стоимости до C-8, который и решает go/no-go по доле. Прокси
как источник цены отвергнут — это возврат дефекта `§−38`. Полное обоснование и
требования к MP-09 — `docs/audit/STOOQ_CONVENTION.md §6`; спецификация
закреплена падающим тестом `test_uncovered_value_reaches_c8_SPEC_FOR_MP09`.

### 2.4 Если конвенция окажется `TOTAL_RETURN`

У Tradernet конвенция `SPLIT_ADJUSTED` (`PHASE_02 §3.1`). Тогда источники нельзя
смешивать в одной матрице (I-7): `manual` работает целиком на Stooq, `freedom` — целиком
на Tradernet, `ChainProvider` между ними внутри одного отчёта **не переключается**.
Это допустимо и даже предпочтительно — каждый отчёт внутренне консистентен.

**Следствие для E-2**, которое надо принять заранее: при разных конвенциях тест
«один портфель через `freedom` и `manual` → одинаковые метрики» перестаёт быть тестом
на равенство и становится сверкой по порогам §8.6 (`PHASE_00 §4`, снятие К-3).

**Важно после решения 2026-07-27:** разные конвенции больше **не** блокируют запуск
`manual`. Раньше расхождение означало «переключение не состоялось, остаёмся на Tradernet»;
теперь Tradernet недоступен юридически, и `manual` в любом случае едет на Stooq.
Расхождение конвенций означает лишь, что отчёты `freedom` и `manual` **не сопоставимы
почисленно** — это факт, который надо честно отразить в CoVe (конвенция уже входит
в строку источника, `PHASE_06 §4`), а не повод остановить фичу. Смешивать источники
внутри одного отчёта по-прежнему запрещено (I-7).

## 5. Риски

| Риск | Митигация |
|---|---|
| Ключ протух посреди процедуры | Зафиксировать тело ответа — это готовый тест-кейс A-1 для Фазы 3 |
| Одного из 10 факторных ETF нет в Stooq | 🔴 **Стоп-фактор запуска.** Обход «`ChainProvider` с Tradernet» после решения 2026-07-27 **недоступен** (I-12). Остаются два пути, оба — решение владельца: (а) исключить фактор из модели (правка `factor_tickers`, то есть математики, с пересчётом снапшотов); (б) искать другой источник, то есть досрочно переходить к Фазе 10 (EODHD). Исполнитель не выбирает |
| Непокрытие KZ/IL или крипто | `manual` остаётся работоспособным, но для части аудитории бесполезным: C-8 заблокирует портфель, где непокрытые позиции дают >10% стоимости. Знать это надо до запуска — потому проверка и перенесена в эту фазу |
| Дневная квота исчерпана на середине | Растянуть на два дня; тело `Exceeded the daily hits limit` — тоже полезная фикстура |
| Процедура даст неоднозначный результат (напр. частичная корректировка дивидендов) | Записать как есть и **не выбирать** конвенцию волевым решением. Неоднозначность = Stooq не годится как источник для ковариации, и это валидный исход фазы |
