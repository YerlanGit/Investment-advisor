## 1. Триггер

Переход инициируется при **~100 активных пользователях**, не раньше.

**Проверка триггера — с поправкой.** Задание считает: «при ~100 MAU выручка ≈ $1 660/мес,
валовая прибыль ≈ $1 570/мес, тариф $399 — около 25% валовой прибыли».

Цифры $1 660 / $1 570 в `docs/business/ECONOMICS.md §4` действительно есть, но строка
называется **«Бета (сейчас)»** и задана как **300 отчётов/мес** — не как «100 MAU».
Переход «300 отчётов ≈ 100 MAU» подразумевает **3 отчёта на пользователя в месяц**;
это допущение автора задания, а не цифра из документа (ошибка E-5).

Вывод от этого не разваливается, но становится условным: при 3 отчётах/пользователя
$399 ≈ 25% валовой прибыли — обоснованно. При 1.5 отчётах/пользователя те же 100 MAU
дают ≈ $830 выручки, и тариф съедает ≈ 50% прибыли — то есть рано, ровно по логике
самого задания («при 50 MAU это было бы ~50% прибыли, то есть рано»).

**Перед стартом фазы измерить фактическое число отчётов на пользователя в месяц**
(пункт ★ в `README.md §7`) и пересчитать. Триггер — не «100 строк в таблице users»,
а «выручка, при которой $399 — четверть валовой прибыли».

## 3. Что даёт переход

| Сейчас (Stooq) | После (EODHD) |
|---|---|
| Ключ через капчу, вручную | Обычный API-ключ, сразу |
| Конвенция определяется эмпирически | Документирована и **выбираема**: `close` сырой, `adjusted_close` = сплиты+дивиденды, Technical API `function=splitadjusted` = только сплиты |
| Нет SLA и опубликованных лимитов | 100 000 запросов/день, 1 000/мин; поддержка 24/7 |
| Отказ = HTTP 200 с текстом | Нормальные коды ответа |
| Юридический статус не установлен | Договор с правом показа данных клиентам |
| Формат тикера `aapl.us` | `AAPL.US` — **совпадает с выходом `resolve_tickers()`** |
| ISIN не поддерживается | `resolve_ticker` умеет ISIN → `SYMBOL.EXCHANGE` |

Режим для миграции — **`function=splitadjusted`**, если Фаза 8 подтвердит, что Stooq
и Tradernet работают в `SPLIT_ADJUSTED`. Тогда переход не меняет ни одного числа в отчётах.

**Про формат тикера — уточнение.** «Совпадает с выходом `resolve_tickers()`» верно
для US-бумаг (`AAPL.US`, `SPY.US`), но `resolve_tickers` (`investment_logic.py:661-720`)
отдаёт также `KSPI.KZ`, `KAP.IL`, `BTC-USD` и прокси-ETF для AIX-нот. Совпадение формата
не означает совпадение **покрытия** — см. §5, покрытие KASE/AIX проверяется поимённо.

## 4. MCP-сервер EODHD — важное разграничение

EODHD предоставляет официальный MCP-сервер (72 read-only инструмента, v1 с ключом в URL,
v2 с OAuth 2.1, открытый исходный код).

**MCP не должен попадать в горячий путь загрузки цен.** Причины: дополнительный сетевой
хоп и JSON-обёртка на каждом запросе при и без того 2–4-минутном отчёте; MCP спроектирован
под интерактивные агентские сценарии, а не под детерминированный батч; отладка сбоя
усложняется лишним слоем. Для `PriceProvider` — **прямой REST**.

Где MCP уместен:
1. **Разработка** — подключить к Claude Code как справочник по API
   (`retrieve_description_by_id` не расходует квоту);
2. **`resolve_ticker`** — разовые операции распознавания тикера и ISIN вне горячего пути;
3. **RAG / нарратив** — новости и фундаментал, где задержка некритична.

Ключ в URL (v1) — учитывать в I-8 при логировании: та же маска `apikey=***`, что и в Фазе 9.

## 5. Оговорка по качеству данных

В материалах EODHD есть **противоречие, которое надо прояснить до подписания**:
FAQ коммерческой страницы утверждает прямые контракты с биржами (Nasdaq Cloud API для США,
LSE, Cboe, 60+ бирж), тогда как дисклеймер в подвале того же сайта говорит, что биржевые
фиды не используются, а данные агрегируются методом VWAP из 100+ OTC и торговых площадок.

Для риск-движка это существенная разница: VWAP-агрегация по OTC даёт другой ряд
доходностей, чем биржевой close, — а именно доходности идут в ковариацию, беты и CVaR.
**Вопрос задать до подписания, ответ зафиксировать письменно.**

## 7. Сверка перед переключением

Та же процедура и те же пороги, что в `PHASE_09 §4.1`: 10 общих тикеров,
`max|Δclose|/close ≤ 0.5%`, корреляция дневных доходностей ≥ 0.999, разница годовой
волатильности ≤ 0.5 п.п., расхождения календаря торговых дней зафиксировать.
Затем `analyze_all` на одном портфеле по обоим источникам: Risk Index, CVaR 95,
топ-3 TRC, факторные беты. **Провал любого порога = переключения нет.**

## 9. Риски

| Риск | Митигация |
|---|---|
| Custom окажется существенно дороже $399 | Триггер пересчитывается по фактической цене, а не по нижней границе. Возможен возврат к Stooq на больший срок |
| Ответ по §5 подтвердит VWAP-агрегацию | Тогда сверка §7 по корреляции доходностей (≥0.999) — решающая. Не прошла → EODHD не годится для риск-движка, каким бы удобным ни был API |
| KASE/AIX не покрыты | Tradernet остаётся обязательным для KZ-бумаг → постоянный `ChainProvider` с двумя конвенциями → **прямой конфликт с I-7**. Решается только если конвенции совпадают; иначе KZ-портфели остаются целиком на Tradernet |
| Миграция «не меняет ни одного числа» окажется неверной | Проверяется сверкой §7 до переключения, а не после. Флаг возвращает прежний источник без передеплоя |
