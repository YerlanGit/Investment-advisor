## 1. Цель

Второй способ ввода для портфелей, которые неудобно набирать текстом. Разбор файла
сводится к тому же `ParseReport`, что и текст (Фаза 4), — вся логика позиций,
кэша, дубликатов и валют переиспользуется без единой ветки.

## 2. Эталонный шаблон

Бот отдаёт по кнопке `.csv` с фиксированными заголовками:

```csv
ticker,quantity,purchase_price,note
AAPL.US,10,150.50,
SPY.US,25,480.00,
CASH:USD,5000,,свободные средства
```

- `note` парсером игнорируется — колонка для пользователя;
- заголовки распознаются регистронезависимо и по синонимам:
  `ticker|тикер|symbol`, `quantity|кол-во|количество|qty`,
  `purchase_price|цена|price|цена покупки`;
- у кэша `purchase_price` пуст — это норма, а не ошибка строки.

**Синонимы уже есть в проекте** — `UniversalPortfolioManager.COLUMN_ALIASES`
(`investment_logic.py:1528-1532`):

```python
'Ticker':         ['Symbol', 'Asset', 'Тикер', 'Name'],
'Quantity':       ['Qty', 'Amount', 'Shares', 'Кол-во'],
'Purchase_Price': ['Buy_Price', 'Price_Buy', 'Entry_Price', 'Цена_Покупки', 'Avg_Price'],
```

Набор задания их **не покрывает** (нет `symbol`, `qty`, `amount`). Правильный ход —
объединение обоих наборов; но `_standardize_columns` (1579) живёт в `investment_logic.py`,
а он ограничен I-2b правкой строк 653-772. Поэтому таблица синонимов **копируется**
в `manual_portfolio.py` как расширенный литерал, с комментарием-ссылкой на оригинал.
Дублирование осознанное: альтернатива — вынести общий словарь в новый модуль
и поправить `investment_logic.py` вне разрешённого диапазона.

## 3. Лимиты — **до** парсинга (Т-11)

Проверяются по метаданным файла, до чтения содержимого:

| Лимит | Значение | Почему |
|---|---|---|
| Размер файла | ≤ 512 КБ | `/tmp` на Cloud Run — это RAM при лимите 2 GiB |
| Строк | ≤ 200 | Портфель на 200 позиций — предел осмысленности отчёта |
| Листов (XLSX) | ≤ 5 | Защита от zip-бомбы в OOXML |
| Расширение | только `.csv`, `.xlsx` | `.xls` (старый бинарный OLE2) **не принимается** |

Превышение → отказ **без чтения содержимого**. Telegram отдаёт размер в метаданных
документа (`message.document.file_size`), поэтому проверка размера делается ещё
до скачивания файла.

### 3.1 Требования к разбору XLSX

Файл приходит из недоверенного источника, поэтому:

- **только значения**, вычисление формул выключено (`openpyxl.load_workbook(data_only=True)`);
- **внешние ссылки не разрешаются** (`keep_links=False`) — иначе ячейка может
  ссылаться на внешний ресурс;
- `read_only=True` — потоковое чтение, чтобы лист на миллион строк не разворачивался в память;
- число строк проверяется **после** открытия, но **до** обхода ячеек, по `ws.max_row`;
- сам `openpyxl` вызывается в отдельном потоке (`run_in_executor`) — разбор блокирующий.

### 3.2 Новая зависимость

`openpyxl` в проекте **нет** (проверено по `requirements.txt`). Добавляется:

```
openpyxl>=3.1,<4.0        # XLSX-разбор ручного портфеля; только чтение, data_only
```

Обязательно: `requirements.lock` регенерируется через
`pip-compile --generate-hashes --strip-extras -o requirements.lock requirements.txt`
**на linux/py3.11** (правило `CLAUDE.md`). Docker и CI ставят `--require-hashes`,
поэтому забытая регенерация ломает сборку, а не тесты.

Импорт — **ленивый**, внутри функции разбора: `openpyxl` не должен попадать
в холодный старт бота ради фичи, которой пользуется меньшинство.

## 4. Разбор → тот же `ParseReport`

```
CSV/XLSX → нормализация заголовков → список кортежей (ticker, qty, price)
         → ParseReport (Фаза 4)  → DataFrame → экран подтверждения (Фаза 5)
```

Правила чисел из §3.2 задания (десятичная запятая, разряды через пробел и `_`)
применяются и к файлу: Excel в русской локали пишет `150,50` и `2 500 000`
с неразрывным пробелом ` ` — его тоже надо убирать, обычным `.replace(" ", "")`
он не ловится. Отдельный тест.

## 7. Риски

| Риск | Митигация |
|---|---|
| `openpyxl` тянет транзитивные зависимости в образ | Единственная транзитивная — `et-xmlfile`, обе чистый Python. Проверить размер образа до/после |
| Ленивый импорт скрывает отсутствие пакета до первого файла | Явная проверка при старте под флагом: `MANUAL_PORTFOLIO_FILES_ENABLED=on` без `openpyxl` → ошибка в лог и авто-выключение фичи, бот работает |
| Дублирование `COLUMN_ALIASES` разъедется с оригиналом | Тест `test_aliases_superset_of_engine` сравнивает копию с `UniversalPortfolioManager.COLUMN_ALIASES` и падает, если оригинал пополнился |
| Пользователь шлёт выгрузку брокера «как есть», с лишними колонками | Лишние колонки игнорируются; отсутствие обязательной → человеческая ошибка с перечнем найденных заголовков |
