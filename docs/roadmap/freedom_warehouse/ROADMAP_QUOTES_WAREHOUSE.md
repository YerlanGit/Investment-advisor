## 0. TL;DR — решение в пяти строках

1. Шов **уже существует**: `PriceProvider` (Фаза 2 плана ручного портфеля). Движок
   не знает, откуда цены. Новый источник = новый класс + строка в `_REGISTRY`.
2. Хранилище отдаёт **RAW**, движок ждёт **SPLIT_ADJUSTED**. Корректировка
   применяется **на чтении**, а не на записи — иначе каждый новый сплит переписывает
   всю историю бумаги задним числом.
3. 🔴 Данные в БД — **происхождением Tradernet**, поэтому новый провайдер обязан
   попасть в `_MANUAL_FORBIDDEN` (I-12). Кэш чужих данных не перестаёт быть чужими данными.
4. 🔴 Строка CoVe «Цены и история активов» **захардкожена** как «Tradernet
   (Freedom Broker)» — после внедрения она начнёт врать. Чинится до включения флага.
5. Failover — **целиком по отчёту** (I-13), никогда по тикеру. Это уже записанное
   правило, а не новое решение.

**Главный выигрыш — не скорость.** Cloudflare-WAF брокера блокирует egress-пул
Cloud Run (`docs/infra/INFRA_NETWORKING.md §1`): бот регулярно получает
`403 + HTML challenge` и пустой набор цен. Хранилище разрывает эту связь — цены
тянет **один** плановый job со статическим IP, а бот читает из БД и в Tradernet
за котировками не ходит вовсе.

## 2. Пять блокирующих находок

Ни одна не видна из ТЗ на ETL — все всплывают только при стыковке с движком.

### 🔴 Н-1. Юридическая граница I-12 наследуется данными

`_MANUAL_FORBIDDEN = frozenset({"tradernet"})` (`price_providers.py:174`) запрещает
показывать данные брокера ручному портфелю: пользователь может не быть клиентом Freedom.

`daily_candles` наполняется **из Tradernet**. Кэш чужих данных не перестаёт быть
чужими данными — юридический статус едет с данными, а не с транспортом.

**Решение:** новый провайдер попадает в `_MANUAL_FORBIDDEN` вместе с `tradernet`.
Тест обязан падать, если его оттуда убрали.

> Ловушка: `provider_for_source` устроен fail-CLOSED (A-3, `price_providers.py:229`) —
> неизвестный источник отвергается. Но `_MANUAL_FORBIDDEN` проверяется **после**
> выбора имени провайдера, и провайдер, забытый в этом множестве, пройдёт молча.

### 🔴 Н-2. Конвенция расходится: RAW против SPLIT_ADJUSTED

`freedom-etl` хранит то, что отдал брокер. `TradernetProvider` объявляет
`SPLIT_ADJUSTED`, потому что `history.py` **на выходе** применяет три слоя:
`corr=1` → `KNOWN_SPLITS` → эвристика скачка > 33% (`history.py:126-129`).

Провайдер поверх сырой БД, объявивший `SPLIT_ADJUSTED`, солжёт; объявивший `RAW` —
честен, но отдаст движку сплит 10:1 как день −90%.

**Развилка (решается в Фазе 1):**

| Вариант | Плюс | Минус | Вердикт |
|---|---|---|---|
| (а) корректировать **на записи** | читатель прост | новый сплит переписывает ВСЮ историю бумаги задним числом; `KNOWN_SPLITS` дублируется в ETL (SSOT ломается) | ❌ |
| (б) хранить RAW + `corporate_actions`, корректировать **на чтении** | сырое неизменяемо и аудируемо; сплит = одна вставка; SSOT корректировки остаётся в `src/` | читатель сложнее на одну чистую функцию | ✅ **принято** |
| (в) хранить только RAW, корректировать эвристикой на чтении | без новой таблицы | эвристика — последний рубеж, а не первый; на неликвиде даёт ложные срабатывания | частично (как слой 3) |

**(б) — стандартная архитектура витрины рыночных данных** и единственная, при
которой запись остаётся append-only.

### 🔴 Н-3. Строка CoVe захардкожена и начнёт врать

`data_lineage.py:104,117` — `source = "Tradernet (Freedom Broker)"` **литералом**,
независимо от того, кто реально отработал.

Инфраструктура для честности уже есть и не используется: `ProviderResult.source`
(ticker → имя) и `ProviderResult.single_source()` (`price_providers.py:74`).

**Решение:** `_tradernet_status` читает источник из `history_result`. Правка мелкая,
но она **обязана** идти ДО включения флага в проде — иначе отчёт подписывает данные
чужим именем, а это ровно тот класс дефекта, против которого построен CoVe.

### 🟠 Н-4. Порог свежести конфликтует с семантикой T-1

`TRADERNET_FRESH_CAL_DAYS = 5` (`data_lineage.py:54`, применяется на `:111`),
старше — статус `stale`.

Хранилище по построению отдаёт **T-1**. В обычный вторник это 1 день — норма.
Но в понедельник после длинных выходных (Рождество, День независимости РК)
последний close легко окажется 4–5 дней назад, и отчёты начнут массово
показывать `stale` там, где данные корректны.

**Решение:** порог считать в **торговых** днях либо задать провайдеру собственный
порог. Не блокирует внедрение, но портит доверие к бейджу — а бейдж тут и есть продукт.

### 🟠 Н-5. Failover нельзя делать по тикеру

`ROADMAP_DATA_RESILIENCE.md §1` и I-13 (`price_providers.py:21`): смешивать
провайдеров в одной ковариационной матрице нельзя — разные конвенции, календари и
правила фиксации закрытия.

Соблазн очевиден: «чего нет в БД — доберём из Tradernet». **Это запрещено.**
Failover — целиком по отчёту.

**Решение:** гейт покрытия ДО расчёта. Не хватило хотя бы одного тикера или
наблюдений — весь отчёт уходит на Tradernet, и это фиксируется в CoVe.

### 3.1 Границы, которые нельзя пересекать

| Правило | Почему |
|---|---|
| `src/` **не импортирует** `freedom-etl/` | разные единицы поставки; в образе бота каталога ETL нет |

## 4. Изменения схемы БД (сторона `freedom-etl`)

### 4.1 Новая таблица `corporate_actions`

```sql
CREATE TABLE IF NOT EXISTS corporate_actions (
    ticker       VARCHAR(20)   NOT NULL,
    action_date  DATE          NOT NULL,      -- дата ex-split
    action_type  VARCHAR(16)   NOT NULL,      -- 'split' | 'dividend'
    ratio        NUMERIC(12,6),               -- 10 = 1 акция → 10 акций
    amount       NUMERIC(12,4),               -- для дивидендов
    source       VARCHAR(32)   NOT NULL,      -- 'known_splits' | 'heuristic' | 'manual'
    PRIMARY KEY (ticker, action_date, action_type)
);
```

**Зачем `source` в ключевых данных.** Событие, найденное эвристикой, и событие из
авторитетной таблицы — разного качества. Без колонки их нельзя ни разделить, ни
пересмотреть, когда эвристика ошиблась.

### 4.2 Колонка конвенции в `daily_candles` — НЕ добавляется

Соблазн: пометить каждую строку конвенцией. Отвергнуто: конвенция — свойство
**ряда на выходе провайдера**, а не строки. `daily_candles` по определению RAW,
и колонка, всегда равная `'raw'`, только создаёт иллюзию выбора.

### 4.3 Read-only роль

```sql
CREATE ROLE ramp_reader LOGIN PASSWORD :'pw';
GRANT CONNECT ON DATABASE quotes TO ramp_reader;
GRANT SELECT ON daily_candles, corporate_actions, tracked_tickers TO ramp_reader;
-- sync_status НЕ выдаётся: это внутренний курсор ETL, боту он не нужен
```

Бот физически не может испортить витрину. Это дешевле любого код-ревью.

### Фаза 3 — `services/quotes_store.py` (L1, read-only)
*Оценка: 1 день. Флаг: `QUOTES_DB_URL` пуст → модуль не активен.*

Тонкий синхронный клиент (`psycopg` pool). **Ничего не решает** — отдаёт
`pd.DataFrame` и покрытие. Весь SQL заперт здесь, как в `db/connection.py` у ETL.

```python

def coverage(tickers, *, days) -> dict[str, int]      # тикер → наблюдений
```

> **Почему синхронный, а не asyncpg.** `get_market_data` — синхронный код внутри
> `analyze_all`, который сам крутится в `run_in_executor`. Тащить туда event loop
> значит городить мост ради драйвера. `psycopg` 3 в sync-режиме здесь честнее.

**Приёмка:** тесты против живого PostgreSQL по образцу
`freedom-etl/tests/test_integration_db.py` (skip без `ETL_TEST_DSN`).

## 6. Нужна ли TimescaleDB — замер, а не вкус

**Объём:** 500 тикеров × 1 260 торговых дней ≈ **630 тыс. строк**.
Даже 5 000 тикеров × 10 лет ≈ 12,6 млн — это всё ещё обычная таблица PostgreSQL с
btree по `(ticker, trade_date)`.

TimescaleDB окупается на 10⁸+ строк и высокочастотной вставке. Здесь — суточная
вставка сотен строк.

**Вывод:** для Cloud SQL (где расширения TimescaleDB **нет**) внедрение возможно
без него. `Database.apply_schema` уже деградирует штатно — проверено на живом
PostgreSQL 16: возвращает `False`, пишет предупреждение, данные и запросы работают.

`docker-compose.yml` с TimescaleDB остаётся для локальной разработки и на случай
роста универсума на два порядка. Решение обратимо: гипертаблица создаётся из
обычной таблицы через `migrate_data => TRUE`, что уже прописано в DDL.

## 7. Что НЕ делается (и почему)

| Не делаем | Почему |
|---|---|
| Дивидендная корректировка (`TOTAL_RETURN`) | движок нигде её не ждёт; смена конвенции меняет ВСЕ доходности — отдельный проект с пересмотром эталонов |
| Перенос `KNOWN_SPLITS` в ETL | нарушит SSOT; таблица остаётся в `src/`, в БД едут её **данные** |
| Отказ от `/tmp`-кэша `history.py` | он обслуживает путь Tradernet, который остаётся резервом |
| Снятие `--max-instances=1` | ограничение от SQLite токеномики, к ценам отношения не имеет |
| Хранение intraday | ТЗ и движок оперируют дневными свечами; `timeframe` в ETL параметризован, но схема заточена под `trade_date` |
| Автосинк универсума со списком брокера | `tracked_tickers` наполняется осознанно; автоподхват втянул бы делистинги и мусор |

## 8. Риски

| Риск | Вероятность | Цена | Митигация |
|---|---|---|---|
| Провайдер забыт в `_MANUAL_FORBIDDEN` | средняя | 🔴 нарушение I-12 | тест, падающий при удалении из множества (Фаза 4) |
| Корректировка сплитов разъехалась между путями | средняя | 🔴 −90% день в ряду | единая публичная функция (Фаза 2) + сверка `\|Δ\| < 0.5 %` |
| CoVe подписывает данные чужим именем | **высокая** без Фазы 5 | 🟠 доверие | Фаза 5 обязательна до включения |
| Частичный failover просочился | низкая | 🔴 смешанная ковариация | тест `single_source() is not None` |
| БД отстала (ETL упал молча) | средняя | 🟠 устаревшие цены | гейт свежести в Chain + алерт на `--once` ≠ 0 |
| Cloud SQL недоступна | низкая | 🟢 | Chain уходит на Tradernet целиком |
