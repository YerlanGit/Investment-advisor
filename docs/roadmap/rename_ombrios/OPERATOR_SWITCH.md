## 0. Перед началом: что понадобится

```bash
# Подставьте свой проект — дальше он используется везде.
export PROJECT_ID="<ваш project id>"
export REGION="us-central1"
export SERVICE="ramp-bot"          # имя сервиса Cloud Run НЕ меняется

gcloud config set project "$PROJECT_ID"
```

🔴 **`export` живёт только до конца сессии.** Cloud Shell переподключается сам
(вкладка в фоне, пауза, обрыв связи), и после этого `$PROJECT_ID` пуст —
команда падает с `The project property is set to the empty string`, а
`| wc -c` печатает `0`, что легко принять за пустой секрет. Инструкция
проходится за несколько заходов, так что при возврате просто повторите обе
строки `export`. `gcloud config set project` сохраняется и повтора не требует.

Узнать сервис-аккаунт, под которым бежит бот (он должен получить доступ к
новому секрету):

```bash
gcloud run services describe "$SERVICE" --region "$REGION" \
  --format='value(spec.template.spec.serviceAccountName)'
```

Если вывод **пустой** — сервис бежит под дефолтным Compute-аккаунтом:

```bash
PROJECT_NUMBER=$(gcloud projects describe "$PROJECT_ID" --format='value(projectNumber)')
echo "${PROJECT_NUMBER}-compute@developer.gserviceaccount.com"
```

Запишите полученный адрес — он нужен на шаге 2. Дальше он обозначен как
`<RUNTIME_SA>`.

## 1. Telegram: перевыпустить токен @Ombri_bot

🔴 **Обязательно.** Токен этого бота однажды был отправлен открытым текстом в
переписку. Такой токен считается известным посторонним: кто угодно с этой
строкой может читать сообщения ваших пользователей и писать от имени бота.

1. Откройте `@BotFather` → `/mybots` → **@Ombri_bot** → **API Token** →
   **Revoke current token**.
2. BotFather выдаст **новый** токен вида `8787642916:AA…`.
3. **Никуда его не копируйте** — ни в чат, ни в заметки, ни в файл в репозитории.
   Он понадобится ровно один раз, на следующем шаге.

Проверьте заодно, что это именно тот бот:

- `/mybots` → @Ombri_bot → **Bot Settings** → имя и описание на месте;
- отправьте боту `/start` — он пока молчит, это нормально: его никто не
  опрашивает.

## 2. Google Cloud: завести секрет и дать к нему доступ

**Ничего, кроме секрета, не создаётся и не меняется.** Бакеты, сервис Cloud
Run, Artifact Registry, VPC — не трогаются.

🔴 **Команды выполняются ПО ОДНОЙ, сверху вниз.** Порядок здесь не
формальность: выдать права можно только на существующий секрет, а секрет без
версии пуст. Вставили блок целиком — получите `404 Secret … not found` от
последней команды (см. §2.5).

### 2.1 Создать секрет

```bash
gcloud secrets create OMBRI_BOT_TOKEN \
  --replication-policy=automatic \
  --project="$PROJECT_ID"
```

Ожидаемо: `Created secret [OMBRI_BOT_TOKEN].`
Если ответ `ALREADY_EXISTS` — секрет уже есть, переходите к 2.2.

### 2.2 Положить в него токен — ТОЛЬКО через консоль

🔴 **Токен не вводится в терминал.** Ни через `read`, ни через переменную, ни
тем более в тело команды. Проверено на живом переезде: за один заход токен
дважды оказался засвечен — сначала обрывок ушёл в секрет вместо значения,
потом полное значение напечаталось на экране и попало в историю оболочки.
Оба раза его пришлось отзывать. Поле в консоли этого класса ошибок не имеет:
значение видно глазами, и его можно сверить до сохранения.

**Cloud Console → Security → Secret Manager → `OMBRI_BOT_TOKEN` →
+ NEW VERSION → вставить в поле «Secret value» → ADD NEW VERSION.**

Перед сохранением сверьте: цифры, `:`, длинный хвост из букв и цифр, в конце
нет пробела и нет пустой строки.

### 2.3 🔴 Проверить у Telegram, что в секрете рабочий токен

Значение читается ИЗ секрета — вы его не вводите. Скопируйте строку целиком,
ничего в ней не меняя:

```bash
T=$(gcloud secrets versions access latest --secret=OMBRI_BOT_TOKEN --project="$PROJECT_ID"); curl -s "https://api.telegram.org/bot${T}/getMe"; echo; unset T
```

Ждём `{"ok":true,"result":{"id":…,"username":"Ombri_bot",…}}`.

* `"ok":false,"error_code":401` — токен отозван или неверен. Вернитесь к §2.2.
* `username` не тот, кому вы пишете, — правится подстановка `_BOT_USERNAME`,
  а не токен.

Почему это стоит отдельным шагом: `logger.info("Starting bot id=…")` печатается
при импорте модуля, ДО первого обращения к Telegram. Мёртвый токен даёт ровно
такую же строку в логах, как живой, и по ней переезд выглядит успешным, пока
бот молчит в чате. `getMe` — единственная проверка, которая это ловит; в логах
косвенный признак — `set_my_commands failed`.

🔴 **Если токен всё-таки засветился** (напечатался на экране, попал в историю,
ушёл в переписку) — он скомпрометирован. Отзовите его в BotFather и почистите
следы:

```bash
unset T; history -c; rm -f ~/.bash_history; history -w
```

### 2.4 Дать сервису право читать секрет

Подставьте адрес из §0 вместо `<RUNTIME_SA>` — **буквально `<RUNTIME_SA>` не
сработает**, это placeholder:

```bash
gcloud secrets add-iam-policy-binding OMBRI_BOT_TOKEN \
  --member="serviceAccount:<RUNTIME_SA>" \
  --role="roles/secretmanager.secretAccessor" \
  --project="$PROJECT_ID"
```

🔴 **Если пропустить, деплой упадёт** на привязке секретов, и прод останется
на предыдущей ревизии. Бот при этом продолжит работать — но обновление не
приедет, и причина будет неочевидной.

Проверка:

```bash
gcloud secrets get-iam-policy OMBRI_BOT_TOKEN --project="$PROJECT_ID"
```

В выводе должен быть ваш `<RUNTIME_SA>` с ролью `secretAccessor`.

### 2.5 Если что-то пошло не так

| Ошибка | Причина | Что делать |
|---|---|---|
| `404 … Secret [projects/…/secrets/OMBRI_BOT_TOKEN] not found` | Пропущен §2.1 — секрета ещё нет | Выполнить 2.1, затем 2.2, только потом 2.4 |
| `INVALID_ARGUMENT … member` | В команду попал буквальный `<RUNTIME_SA>` | Подставить адрес из §0 |
| `ALREADY_EXISTS` на 2.1 | Секрет уже создан | Пропустить 2.1 |
| `PERMISSION_DENIED` | Не тот проект в `gcloud config` | `gcloud config set project "$PROJECT_ID"` |
| Сборка падает сразу, до шага build, с жалобой на подстановку | Переменные добавлены в триггер ДО мержа кода — конфиг о них не знает (`MUST_MATCH`) | Убрать их из триггера, влить код в `main`, вернуть (§2.7) |
| `The project property is set to the empty string` (и `wc -c` даёт `0`) | Cloud Shell переподключился, `$PROJECT_ID` потерян | Повторить обе строки `export` из §0 — это не пустой секрет |
| Бот молчит в Telegram, хотя в логах есть `Starting bot id=` | Токен отозван/неверен: эта строка печатается ДО обращения к Telegram | `getMe` (§2.3); в логах ищите `set_my_commands failed` |
| Секрет обновили, а бот всё равно молчит | Работающий контейнер держит прежнее значение | Поднять новую ревизию: `gcloud run services update ramp-bot --region=us-central1 --update-secrets=OMBRI_BOT_TOKEN=OMBRI_BOT_TOKEN:latest` |
| Токен напечатался на экране / попал в историю | Введён в терминал вместо поля консоли (`${#T}` — это «длина T», а не placeholder) | Отозвать в BotFather, почистить историю, повторить §2.2 через консоль |
| Команда «висит», приглашение не возвращается | В `versions add` не попал префикс `printf … \|` — читается клавиатура | **Ctrl-C** (не Ctrl-D), затем §2.2 одной строкой |
| В секрете оказался мусор вместо токена | Версия создана из набранного текста | Добавить верную версию (§2.2) — `:latest` укажет на неё; мусорную `gcloud secrets versions destroy N --secret=OMBRI_BOT_TOKEN` |

### 2.6 Старый секрет НЕ удалять

`RAMP_BOT_TOKEN` остаётся в проекте: это ваш путь отката. Удалить его можно
через неделю-другую после того, как новый бот отработает без нареканий.

Убедиться, что оба на месте:

```bash
gcloud secrets list --project="$PROJECT_ID" --filter="name~BOT_TOKEN"
```

## 2.7 🔴 СНАЧАЛА влить код в `main`, и только потом трогать триггер

**Порядок здесь обязателен, и нарушение ломает сборку.**

Cloud Build по умолчанию работает в режиме `MUST_MATCH`: подстановка, которой
нет в `cloudbuild.yaml`, — ошибка сборки, а не «просто лишняя переменная».
Подстановки `_BOT_TOKEN_SECRET` и `_BOT_USERNAME` появились вместе с кодом
переезда (`§−101`). Пока этот код не в `main`, конфиг о них не знает.

Добавите их в триггер раньше мержа — **сборка упадёт до первого шага**, деплоя
не будет, прод останется на старой ревизии.

Правильная последовательность:

```
1. Влить ветку переезда в main (PR).
2. Дать сборке отработать. Она НИЧЕГО не переключает: подстановки в конфиге
   держат прежний секрет и прежний хэндл, бот остаётся @KEN_investment_bot.
3. Убедиться, что бот жив: /start у @KEN_investment_bot отвечает.
4. И только теперь — §3: добавить в триггер две подстановки и запустить сборку.
```

Проверить, что код доехал до `main`, можно по самому конфигу:

```bash
git -C <репозиторий> fetch origin main
git -C <репозиторий> show origin/main:cloudbuild.yaml | grep -c "_BOT_TOKEN_SECRET"
```

Ноль — код ещё не в `main`, к §3 переходить рано. Ожидаемо **2** (объявление
подстановки и её использование в шаге деплоя).

## 3. Cloud Build: переключить ДВЕ подстановки — одновременно

Cloud Console → **Cloud Build** → **Триггеры** → ваш триггер → **Изменить** →
раздел **Переменные подстановки**.

Добавьте (или измените) **обе** строки:

| Переменная | Значение |
|---|---|
| `_BOT_TOKEN_SECRET` | `OMBRI_BOT_TOKEN` |
| `_BOT_USERNAME` | `Ombri_bot` |

🔴 **Только вместе.** Хэндл вшивается в готовый HTML-отчёт и становится
кнопкой «Применить идею». Поменяли хэндл раньше токена — кнопка ведёт к боту,
которого ещё не опрашивают; позже — к боту, которого уже не опрашивают. Отчёт
статичен: ссылку в нём задним числом не поправить. В репозитории на это стоит
тест, но **значения в триггере тест не видит** — здесь пару держите вы.

🔴 **Не оставляйте `_BOT_USERNAME` пустым.** Пустое значение не равно
«по умолчанию как было»: код воспримет его как «не задано» и подставит
`Ombri_bot`, то есть выполнит половину переключения молча.

Два уточнения, чтобы не спотыкаться:

- Обе переменные **уже объявлены** в `cloudbuild.yaml`, поэтому добавление их
  в триггер безопасно. Cloud Build по умолчанию (`MUST_MATCH`) ругается на
  переменную, которой нет в конфиге, — здесь этого не случится.
- Без `@`. Пишется `Ombri_bot`, а не `@Ombri_bot` (лишнюю `@` код срежет, но
  лучше не проверять).

Затем запустите сборку: **Выполнить триггер** (или просто push в ветку).

## 4. Проверка после деплоя — четыре пункта

### 4.1 Бот поднялся под НУЖНЫМ аккаунтом

```bash
gcloud logging read \
  'resource.type="cloud_run_revision"
   resource.labels.service_name="ramp-bot"
   textPayload:"Starting bot id="' \
  --limit=5 --project="$PROJECT_ID" --format='value(textPayload)'
```

В строке `Starting bot id=<цифры>` **цифры до двоеточия** обязаны совпасть с
началом нового токена (`8787642916:AA…` → `id=8787642916`).

🔴 Это единственная проверка, которая ловит подмену значения: если в новый
секрет случайно попал СТАРЫЙ токен, всё остальное выглядит нормально, а бот
работает под прежним аккаунтом при новых ссылках в отчёте.

### 4.2 Предупреждения об устаревшем имени НЕТ

```bash
gcloud logging read \
  'resource.type="cloud_run_revision"
   resource.labels.service_name="ramp-bot"
   severity>=WARNING
   textPayload:"устаревший"' \
  --limit=5 --project="$PROJECT_ID" --format='value(textPayload)'
```

Пусто — правильно. Строка про «взял устаревший `RAMP_BOT_TOKEN`» означает, что
`_BOT_TOKEN_SECRET` не переключился (бот работает, но переезд не состоялся).

### 4.3 Данные на месте

В Telegram откройте **@Ombri_bot** → `/start`.

```
□ Бот отвечает (первое сообщение обязаны отправить вы — боты не пишут первыми)
□ Меню анализа, а НЕ анкета из 6 вопросов
  (анкета = профиль не найден → сообщите, не проходите её заново)
□ /balance показывает ваш прежний баланс токенов
□ Мандат и риск-профиль на месте
```

### 4.4 Кнопка в новом отчёте ведёт на нового бота

Сгенерируйте один отчёт (**Базовый** — 1 токен) и в нём нажмите
**«Применить идею»**: модальное окно должно открывать `t.me/Ombri_bot`.

## 5. Старый бот @KEN_investment_bot

Отдельно закрывать его **не нужно и нечем**: после шага 3 его токен никто не
опрашивает, сообщения уходят в очередь, которую никто не читает. Бот
становится недоступен всем автоматически.

```
□ НЕ удалять бота в @BotFather.
  Удаление освобождает хэндл — его зарегистрирует кто угодно и получит
  входящие по ссылкам из ваших СТАРЫХ отчётов.
□ Рекомендуется: @BotFather → @KEN_investment_bot → Revoke current token.
  Утёкшая копия старого токена станет бесполезной. Бот при этом остаётся вашим.
□ TG_ALLOWED_USERS не ставится: @Ombri_bot остаётся открытым (ваше решение).
```

**Что в старых отчётах.** Кнопка «Применить идею» в уже выпущенных отчётах
навсегда ведёт на `t.me/KEN_investment_bot`: HTML статичен и лежит в GCS.
Открывшийся бот просто не ответит. Это принято осознанно — при одном
пользователе перегенерация старых отчётов не окупается.

## 6. Откат

Если что-то пошло не так — вернуть **обе** подстановки и передеплоить:

| Переменная | Значение отката |
|---|---|
| `_BOT_TOKEN_SECRET` | `RAMP_BOT_TOKEN` |
| `_BOT_USERNAME` | `KEN_investment_bot` |

Код читает `RAMP_BOT_TOKEN` вторым именем, поэтому откат безопасен в обе
стороны. Ничего удалять и восстанавливать не нужно — секрет на месте.
