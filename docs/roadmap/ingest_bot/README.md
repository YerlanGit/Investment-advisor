## Зачем отдельный проект, а не фаза Manual Portfolio

База котировок Stooq принадлежит проекту `manual_portfolio/` — там она
спроектирована, там регламент оператора. Но **бот-загрузчик** — это отдельная
единица поставки: свой Cloud Run сервис, свой Telegram-токен, свой
сервис-аккаунт и свой бакет. Ровно тот же случай, что `freedom-etl/`, и та же
причина: смешать их значило бы получить PR, в котором нельзя отдельно проверить
«данные легли правильно» и «человек смог их залить».

Поверхность бота при этом шире одной базы (`DATA_SURFACE.md`), поэтому
складывать его в `manual_portfolio/` было бы неверно и по содержанию.

## Четыре решения, на которых держится проект

1. **Тот же образ, другой сервис.** `finance/stooq_ingest.py` уже лежит в
   деплой-образе и покрыт тестами — копировать его во второй репозиторий нельзя.
2. **Публикация через CAS.** Скачать объект → применить локально → загрузить с
   `if_generation_match`. Превращает договорённость «оператор должен быть один»
   в механизм.
3. **Отдельный бакет `ramp-bot-quotes`.** Сегодня база котировок лежит рядом с
   балансами и зашифрованными ключами брокера. Появление писателя это меняет:
   «не трогать» должно стать отсутствием права, а не просьбой.
4. **Fail-closed доступ.** Пустой список админов = никого. Копировать
   `WhitelistMiddleware` главного бота нельзя — он fail-OPEN по решению для беты.

## Чего бот не делает никогда

* не собирает базу с нуля (архив 0.84 ГБ через Telegram не проходит);
* не создаёт пустую базу, если объекта в бакете нет, — отказывает громко;
* не заводит новые бумаги дневной дельтой (`allow_new=False`);
* не имеет прав на `tokenomics.db` и `users_vault.db`;
* не строит отчёты и не знает про `aiogram`-флоу главного бота.
