## 2. Что мешает — по цене ошибки

### 2.1 🔴 Функции-континенты: `analyze_all` = 1022 строки

| Функция | Строк |
|---|---|
| `investment_logic.analyze_all` | **1022** |
| `pdf_payload.build_payload` | **819** |
| `ai_narrative._user_prompt` | **653** |
| `tg_bot._run_analysis_background` | **353** |
| `simulate.simulate_after_plan` | 317 |
| `premium_payload._map_deep` | 295 |

Это **главная** проблема читаемости. Последствия для агента конкретны:

- прочитать функцию целиком = сжечь заметную долю контекста; читать по кускам —
  потерять связи между началом и концом;
- любая правка внутри 1022 строк требует доказать, что не задета соседняя логика,
  а доказать это чтением нельзя — только тестами;
- поиск «где считается X» вырождается в grep по всему файлу, потому что имя
  функции ничего не сообщает: в `analyze_all` живёт ВСЁ — от нормализации фрейма
  до Black-Litterman и сборки 31-ключевого словаря.

**Инцидент этой сессии.** Метод `_normalize_positions` был добавлен рядом с
`_standardize_columns` — и оказался на `UniversalPortfolioManager`, тогда как тесты
писались против `MAC3RiskEngine`. Причина ровно одна: **три класса живут в одном
файле на 2852 строки**, и граница между ними не видна в точке правки.

### 2.2 🔴 `results{}` — контракт из 31 ключа без схемы, который читают 17 модулей

```
performance_table, risk_matrix, total_portfolio_pnl, total_value, portfolio_metrics,
leverage_metrics, port_log_returns, risk_mandate, risk_free_rate, benchmark_comparison,
profile_benchmark_ticker, benchmark_factor_profile, period_returns_table,
return_series_coverage, proxy_substitutions, priced_at_cost, merged_positions,
dropped_rows, stress_scenarios, expected_effect, cds_summary, history_result,
sector_exposure, factor_scores, regime, macro_drivers, technicals, asset_scores,
black_litterman, action_plan, smart_money
```

Читателей: `pdf_payload` (26 ключей), `ai_narrative` (16), `data_lineage` (14),
`html_renderer` (12), `premium_payload` (7), ещё 12 модулей.

Ни dataclass, ни TypedDict, ни валидации. Чтобы узнать, что лежит в
`results["expected_effect"]`, надо найти место сборки **внутри функции на 1022
строки**. Опечатка в ключе у потребителя даёт не ошибку, а тихое `None` → «—» в
отчёте.

**Это не теория.** Дефект **R-6** (аудит 30.07) ровно такой: `actionPlan[].reason`
вычисляется движком («deferred (turnover cap)», «вне модели: история < 60 торг.
дней», «BL расходится с сигналом») и **молча теряется** мапперами Premium, а
`scores[].reason` читается шаблоном, но источником не производится вовсе. Полгода
объяснений не доезжало до читателя, и ни один тест этого не заметил — потому что
терять ключ в нетипизированном словаре разрешено.

### 2.3 🟠 Корневой `CLAUDE.md` превратился в журнал

| Замер | Значение |
|---|---|
| Размер | 21 010 символов ≈ **5 250 токенов В КАЖДОЙ СЕССИИ** |
| Строк | 30 (!) — то есть текст «слипся» |
| Самая длинная строка | **8 594 символа** (строка 15) |
| В строках >400 символов | 92% файла |
| Дат вида `2026-07-…` | 26 |
| Ссылок на раунды/находки в строке 15 | 35 |

Строка 15 начинается как правило («запускай тесты с `PYTHONPATH=src`») и дальше
уходит в пересказ раундов 27–38. Это **журнал изменений внутри инструкции**.
Для агента: пять тысяч токенов постоянной нагрузки, из которых работает несколько
сотен, а остальное — история, уже записанная в `AUDIT.md`.

Контраст нагляден: `src/finance/CLAUDE.md` — 2 092 символа, максимальная строка
87 символов, и он полезнее корневого.

**Инцидент этой сессии.** Команда запуска тестов в корневом `CLAUDE.md` была
указана БЕЗ `PYTHONPATH=src` и не работала. Правило было неверным — и это не
заметили, потому что его невозможно прочитать глазами внутри мега-строки.

### 2.4 🟠 Тесты названы по фазам, а не по модулям

**41 из 46 файлов (89%)** называются `test_phase<N>_*.py`. Вопрос «какие тесты
покрывают `finance/regime.py`» решается только grep'ом — ответ: **7 разных файлов**,
ни один не назван «regime». Для `premium_payload` — 8 файлов.

Цена: перед правкой модуля агент не может дешёво узнать, что именно защищено.
Он либо гоняет весь набор (2 минуты) на каждую гипотезу, либо правит вслепую.

Номер фазы — это КОГДА написано, а модуль — ЧТО проверяется. Навигация нужна по
второму.

### 2.5 🟡 Границы модулей размыты: приватные имена ходят между файлами

7 межмодульных импортов `_private`-имён, включая инверсии слоёв:

```
html_renderer      → from tg_bot import _sparkline_svg          # слой отчёта тянет из бота
data_lineage       → from pdf_payload import _model_display_name # движок тянет из презентации
pdf_payload        → from agent.gatekeeper import _classify_to_asset_key
ai_narrative       → from agent.gatekeeper import _classify_to_asset_key
tg_bot             → from finance.broker_api import _classify_instrument
demo_portfolio     → from finance.broker_api import _classify_instrument
simulate           → from finance.action_plan import _action_signed_delta
```

Плюс тесты импортируют приватные функции из **22 модулей** (68 импортов из
`ai_narrative`, 54 из `pdf_payload`). Следствие для агента: **непонятно, что можно
менять безопасно**. Переименование внутренней функции ломает тесты, хотя поведение
не изменилось, — значит «внутреннего» в проекте фактически нет.

### 2.6 🟡 Нет SSOT классификации инструментов (дефект A-5)

Вопрос «какие тикеры — облигации» решается независимо в **шести** местах
(`asset_taxonomy`, `gatekeeper`, `scoring`, `broker_api`, `sec_edgar`,
`scoring_orchestrator`). Замерено: `VWOB`/`VCIT`/`SHV` не знает никто, `EMB`
отсутствует в двух копиях, `TNX` (это ИНДЕКС, не ETF) есть только в `gatekeeper`.

Для агента это ловушка: правишь одну копию, проходишь тесты, а в отчёте бумага
остаётся классифицированной по-старому. В живом отчёте это уже видно (**R-11**):
AIX-нота одновременно «Облигации» в мандатной панели и «Акции KZ» в таблице позиций.

### 2.7 🟡 Два окружения расходятся, и CI это не ловит

`Dockerfile` копирует только `src/`, `tests/`, `SYSTEM_PROMPT.md`,
`requirements*.txt` — каталога `design/` в образе нет. GitHub CI работает на полном
чекауте. Значит **зелёный CI не означает, что деплой пройдёт**.

**Инцидент этой сессии:** три теста читали `.jsx` безусловно → CI зелёный, деплой
упал с `FileNotFoundError`. Конвенция «skip при отсутствии `design/`» в проекте
существовала (`test_phase31`), но нигде не была записана как правило. Теперь
записана в `CLAUDE.md`.

### 2.8 🟢 Мелочи

- Nav-анкеры покрывают **25 из 60** файлов `src/`; из крупнейших не покрыты
  `sec_edgar.py` (742), `scoring_orchestrator.py` (677), `client.py` (530).

## 3. Что улучшить — по отдаче на усилие

| # | Действие | Отдача | Стоимость |

| **1** | **Ужать корневой `CLAUDE.md` до ~120 коротких строк.** Оставить: стек, инварианты, обязательные команды, «где что лежит», ссылки. Всю историю раундов — вынести в `AUDIT.md` (она там уже есть). Правило: одна мысль = одна строка ≤120 символов | −4 000 токенов в КАЖДОЙ сессии + правила снова читаемы | 1 час |
| **2** | **Типизировать `results{}`** через `TypedDict` (или dataclass) в отдельном `finance/contracts.py` | Опечатка ключа становится ошибкой; потребитель узнаёт форму, не открывая `analyze_all`; дефекты класса R-6 перестают быть возможными | 3–4 часа |
| **3** | **Разрезать `analyze_all` на именованные этапы** (`_prepare_positions` → `_load_prices` → `_build_risk_model` → `_score_assets` → `_build_results`), сохранив порядок и поведение | Имя этапа отвечает на «где считается X» без чтения 1022 строк | 1 день, требует аккуратности |
| **4** | **Переименовать тесты по модулю**: `test_regime_*.py` вместо `test_phase10_*.py` (номер фазы — в docstring) | «Что покрывает мой модуль» — за один `ls` | 2 часа, механически |
| **5** | **SSOT классификации инструментов** — одна таблица, шесть потребителей | Снимает A-5 и R-11; исключает «поправил одну копию из шести» | полдня |
| **6** | **Разнести `investment_logic.py`** (2852 стр, 3 класса) хотя бы на движок и менеджер портфеля | Граница классов становится видимой в точке правки | полдня |
| **7** | Публичные API вместо приватных импортов: то, что нужно двум модулям, — не `_private` | Появляется реальная «внутренняя» зона, которую можно менять свободно | 2 часа |
| **8** | Nav-анкеры для непокрытых крупных модулей (`sec_edgar`, `scoring_orchestrator`, `client`) | Достраивает уже работающий индекс | 30 минут |

**Порядок неслучаен.** №1 и №2 дают наибольший эффект при наименьшем риске: они не
меняют поведение вообще. №3 и №6 — рефакторинг с риском, их стоит делать после
№2, потому что типизированный контракт превращает разрезание функции из «страшно»
в «проверяемо».

## 4. Главный вывод

Проект **документирован лучше, чем структурирован**. Слой доков (nav-анкеры,
вложенные `CLAUDE.md`, обратная карта CODE→DOC, журнал раундов) спроектирован
под агента осознанно и работает — именно он позволил провести сквозной аудит за
часы, а не за дни.

Ограничивают три вещи, и все три измеримы: функции-континенты
(`analyze_all` 1022 строки), нетипизированный контракт из 31 ключа на 17
потребителей, и корневой `CLAUDE.md`, который из инструкции превратился в журнал
на 5 250 токенов.

Ирония в том, что документация компенсирует проблемы кода — и потому их
маскирует. Пункты 1–2 из таблицы стоят полдня и снимают больше половины
издержек: инструкция снова становится читаемой, а контракт — самоописываемым.
